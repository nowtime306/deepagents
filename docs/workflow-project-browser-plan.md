## 设计与开发顺序

1. **结构化工作流与复用**：旧的文本工作流保持兼容；输入/输出支持有界 JSON Schema 子集，拒绝远程引用、执行表达式和未支持关键字。新增引用不可变发布版本的子工作流、数组迭代和并行节点，最多两层、十项迭代、两路并发，结果保持输入顺序。所有子调用共享根运行的调用、Token、取消与资源授权，不能通过嵌套扩大权限。中文画布提供参数、Schema 编辑与测试结果。
2. **受限工作流工具与恢复**：Ask 只能使用智能体明确绑定且已发布、只读的版本；继承父运行预算与租约。错误分支只处理确定的失败，不自动重试结果未知的外部请求。人工审批与代码节点复用任务工作台的持久授权、运行环境和操作记录；没有跨重启恢复证据前不开放入口，也不在宿主直接运行用户代码。
3. **会话分支**：从本人会话选定消息创建独立分支；编辑用户提问创建新分支，原记录不变。历史只作为上下文导入，不重放工具；文件复制并校验，源会话删除不破坏分支；后续执行重新检查当前资源权限。上下文和附件超限明确拒绝，账本不复制成新的消费。
4. **成果查看**：在已有下载与逐行差异之上增加文本、图片预览；通过不可猜测的成果 ID、本人归属、字节数与摘要校验取文件。文本以纯文本显示，网页/SVG 不执行；大文件给出下载入口，跨用户访问和文件被替换均拒绝。
5. **浏览器工作台**：任务内持久浏览器进程、截图与活动标签状态；人工接管必须先暂停智能体，并持有短期控制权；仍校验任务归属、有效期和授权域名。登录状态按任务隔离，凭证不进入模型上下文、公开事件或工作区成果。需要实际镜像与本机浏览器验证后才开放。

## 成功标准

- 先在隔离数据库验证旧流程兼容、JSON 类型/大小边界、嵌套与递归拒绝、并行顺序、根预算竞争、撤权和取消；实际本机协议服务记录请求次数及用量。
- 验证分支检查点独立、编辑不改变原会话、附件校验、源删除与越权；不复制模型费用或重放历史工具。
- 验证成果损坏、跨用户、脚本型内容、大文件及移动端；验证真实浏览器连续两次操作保持页面状态、暂停/接管/恢复互斥和重启后的明确状态。
- 每项完成后进行针对性测试；阶段交付前运行完整后端、Chrome 页面、TypeScript、静态检查与生产构建，应用迁移前做备份并隔离恢复，重启服务后复验。
- 将“已实现”“本机验收”“真实外部效果待接入”分开记录；阶段七、八继续按原计划推进。
