## 3. 可复现问题与本轮取舍

### UX-01 / P2：知识检索页面暴露模型内部使用指令

重现：知识库→检索测试，先输入无命中问题，再输入星桥保修。当前页面在候选数量后显示“请明确说明未找到资料，不得声称知识库支持答案或编造引用”“仅引用实际支持结论的片段ID”等段落。它们适合提供给模型，却让普通用户像在读系统提示词；命中结果正文/来源与分数本身正确。

最小需求：仅调整页面显示，把模型使用约束留在后端/工具原文中；用户看到“未找到相关资料，可换一种问法或补充文档”或“找到1条候选资料，请核对内容及适用范围”。保留“分数不是回答置信度”、来源定位和真实结果，不删除安全判断或伪造答案。无需新服务/迁移，不改检索算法。

验收：0/1命中正常，页面不再出现命令模型如何作答的原文；真实片段/来源/分数仍可查看；协议和提示约束不变。产品建议可纳本轮小改，根协调者确认后开发/审查/测试。

### UX-02 / P2：技能YAML元信息被渲染成正文大标题

重现：能力中心→Skills→ux-report-style→查看资源。SKILL.md头部name/description被Markdown的分隔线解释为大标题，弹窗出现巨大的“name: ux-report-style description: Virtual report example”，与已有标题重复，占据主要空间。

最小需求：预览SKILL.md时将已校验的YAML头与正文分开，名称/用途以元信息呈现，正文从头部结束后渲染；参考资料保持普通Markdown/文本查看。保留真正原文件给Agent及导出，不改变Skill版本、绑定或原始资产。可采用既有元信息而不引新YAML依赖。

验收：SKILL.md不出现伪造的大name/description标题；原正文可读；非SKILL.md参考资源照常；真实文件不被改写；恶意HTML仍按原渲染限制处理。该问题也影响新录制生成Skill的查看体验，建议随BSK前端小改收口。

### UX-03 / P3：高级设置集中展示导致Agent表单偏长

真实观察：简单编辑一个资料助手也会看到团队委派次数、资源包含约束等长说明。建议后续以基础配置/高级协作渐进展开，保留原权限与字段；当前取消/保存入口清楚，未发现挡住主路径的故障。本轮不新增大型Agent编辑器改造。

### UX-04 / P3：初次加载瞬间误显示“尚未配置模型”

登录后的第一次AX状态先显示尚未配置，随数据加载正确变为本地虚拟模型（非生产）。建议加载态使用“正在读取模型”，与真实空配置区分；本轮未测精确时间/慢网，不把瞬时观察冒充性能基准或丢配置bug。可作为后续小体验项，不阻塞WVR/BSK。

## 4. 与官方项目调研的衔接

[13项目官方研究](agent-platform-optimization-requirements.md)提供能力借鉴，实际页面证据决定优先级。Dify/n8n的设计、测试、发布分离支持WVR已有规划；BrowserSkill应在真实轨迹审阅→参数化→Skill→显式本机授权→整路径审批之间清楚交接，不能让用户误以为普通Skill一绑定就自动获得本机登录身份。Deep Agents的Skill按需读取也不要求把YAML展示成正文。

本次不因OpenClaw stars更多就改全部视觉，不添加客服工单、WebRTC、全量数据分析或所有上游节点。新增小范围建议只有UX-01/02，低优先的UX-03/04留需求池。现有通过路径继续保持；未做移动端、文件上传/删除、真实网站及所有权限组合测试，不能写整系统无bug。
