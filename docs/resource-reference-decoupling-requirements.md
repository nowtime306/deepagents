# 资源引用解耦与配置变更追溯优化需求

- 产品：知行平台
- 日期：2026-11-03（北京时间）
- 文档版本：v1.0
- 需求编号前缀：RDC
- 状态：产品需求，待开发、审查、测试及上线；本文不代表功能已实现
- 依据：本会话已确认的资源关联原则及当前源码只读检查

## 1. 背景与问题

用户通过对话创建定时任务时，系统返回 `AGENT_MODEL_CHANGED`。检查发现，“自动任务助手”发布版绑定的模型配置修订为 1，当前配置修订为 2；模型本身仍启用，类型及协议支持聊天。后台仅因配置修订不同，便拒绝创建任务。

类似检查还出现在团队成员、Skills、MCP、工作流、历史回退、任务执行、模型路由、索引、评测、仓库和通知中。当前部分逻辑将“配置修订不同”同时视为“资源不可用”“审批失效”或“必须重新发布”，没有区分实际变化。

配置修订号仍有价值：用于并发编辑保护、修改历史和运行追溯。本需求不删除修订号，而是解除它与跨资源可用性的笼统绑定。

用户已明确接受：旧智能体版本回退后，调用效果随模型当前配置变化是正常现象。平台应提供足够的修改记录，帮助定位变化原因，不承诺历史输出完全复现。

## 2. 产品目标与成功标准

1. 修改模型地址、密钥、参数等配置后，后续任务可使用最新配置，已有智能体版本无需重新发布。
2. 团队和工作流不因无关配置维护而逐层失效；工作流旧版可恢复为当前发布版，并使用当前可兼容资源。
3. 一次运行使用明确的配置，普通配置更新不打断已开始的运行，也不悄悄改变其执行逻辑。
4. 从失败运行可查到实际使用的智能体/工作流版本、资源配置和相关修改记录。
5. 权限撤销、资源停用、实际不兼容、审批对象变化仍被正确拦截，不能以解耦为由绕过。

## 3. 统一规则

### 3.1 资源 ID、业务版本与配置修订分开

- **资源 ID**：标识同一资源，如模型 A、知识库 B、MCP C。
- **业务发布版本**：保存智能体或工作流自身逻辑，如提示词、节点、连线、参数、预算、资源绑定和执行策略。
- **配置修订**：记录同一资源配置的修改，不自动使引用它的发布版本失效。
- **运行快照**：记录本次实际采用的业务版本、配置修订和可追溯配置内容。

智能体发布 v1 绑定模型 A；A 的配置由修订 2 更新为修订 3，下一次运行仍为智能体 v1，但采用 A 的修订 3。将智能体绑定模型从 A 改为 B，则属于智能体自身逻辑修改，应走智能体版本流程。

### 3.2 外部配置与明确业务版本的引用语义

- 模型、连接及其他未指定业务版本的资源，通过 ID 获取运行开始时的最新可用配置。
- 显式绑定的成员智能体版本、子工作流版本继续固定其业务逻辑；发布新版本不自动替换已有明确引用。
- Skills 本期按资源 ID 获取当前可用内容，运行时固定正文/脚本摘要及版本。已有旧修订字段仅作为历史依据，不因其与当前修订不同而要求重新发布整个智能体。
- 工作流 Agent 节点如当前仅保存 Agent ID，本期不额外引入版本选择功能；采用本次解析的智能体配置并记录快照。已经明确保存版本 ID 的入口不得退化为读取最新草稿。
- 删除、停用、下线或撤销授权与普通更新不同，必须继续即时生效。

### 3.3 运行配置的确定时机

- 保存草稿、创建定时规则或任务入队，不等于本次配置已最终确定。
- 在实际开始执行、首次外部调用前，确定本次需要的资源配置；同一资源在本次运行中复用同一快照。
- 团队和工作流可预先解析声明的依赖。确需执行中才确定的资源，在首次使用时固定并记录；不得在后续调用中无记录地切换。
- 按能力读取同一份配置并完成实际调用，避免校验使用一份配置、调用使用另一份配置。
- 普通更新后，当前进程可继续使用已确定的配置；新运行使用最新配置。启停、权限、取消和审批校验仍执行。

### 3.4 任务恢复

- 短暂暂停或恢复时，优先沿用本次已确定的配置；普通配置更新不应直接要求新建任务。
- 进程重启后，如果能够恢复原运行所需的非敏感配置并安全解析凭据，则继续原配置。
- 如果旧凭据无法恢复，可使用同一资源当前凭据，并记录“恢复时凭据已更新”；不得静默变更模型、服务目标或已批准操作。
- 必须切换其他配置才能继续时，进入“待确认恢复”，列出变更及兼容结果；用户确认后记录新执行阶段，不伪装成全程使用同一配置。
- 不因恢复而重复已完成写操作；结果未知的操作沿用现有核对流程。
- 不为满足恢复而新增密钥明文历史，也不承诺已失效凭据继续可用。

## 4. 优化需求

### RDC-01 智能体及自动任务解除模型修订绑定（P0）

智能体发布版只将模型 ID 作为引用关系。读取已发布智能体、创建/启用自动任务、批量任务及实际调度时，不再因模型配置修订不同而拒绝。

仍检查模型存在、启用、协议与用途兼容，以及图片、工具调用、联网等实际需要的能力。能力未知时明确提示需验证，不把未知当作支持。

验收：发布智能体 v1 后更新模型配置，使用 v1 创建并执行普通对话及自动任务成功；模型删除、停用或改成向量用途时准确拒绝，草稿失败不误报为任务创建成功。

### RDC-02 团队成员解除模型变更的级联发布（P0）

成员智能体仍可固定业务版本，其模型采用当前可兼容配置。成员模型维护不要求重新发布成员或主智能体。角色、委派目标、成员版本及资源授权变更仍按团队自身逻辑处理。

验收：只更新成员模型配置，旧团队发布版仍能执行；运行详情分别列出主智能体版本、成员版本和各自实际模型配置；移除成员授权或下线成员版本仍被拦截。

### RDC-03 工作流及历史回退解除外部配置修订绑定（P0）

发布版本保留原节点、连线、参数、指令、Schema、预算及明确业务版本引用。运行时解析当前外部配置，不以旧 `resource_pins` 与当前配置不同为唯一拒绝依据。

历史 v1 可直接设为当前发布版，并使用当前可兼容模型和连接配置，无需为了凭据或地址更新复制并重新发布相同流程。草稿修改后的整体测试门槛继续保留，不将其与外部资源普通更新混为一谈。

只读执行、持久任务、外部 API、Ask/Work 调用和嵌套子流程采用相同规则。切换当前发布指针不改变明确绑定 v2 的调用，也不改变进行中运行。

验收：v1/v2 发布后修改模型配置，可切回 v1 并执行；节点及子流程业务版本准确，实际模型为当前配置。缺失资源或参数结构不兼容时，指出节点、资源、原因及修复入口，不统一要求重发整条工作流。

### RDC-04 已有运行不被普通配置更新中断（P0）

清理 Ask 后台、Work 后台、公共调用记账、团队、工作流及原生联网中以通用配置修订变化为理由的重复阻断。索引、媒体及其他使用同一公共调用链的功能同步适配。

记账校验应关联本次实际配置快照，不应为了通过校验而伪造当前修订。按第 3.3、3.4 节处理配置确定及恢复。

验收：任务排队期间更新配置，开始时采用新配置；任务执行多次模型调用期间更新配置，当前运行继续用原快照，新运行采用新配置；取消和停用仍有效。暂停、重启及恢复不重复副作用。

### RDC-05 配置修改记录（P0）

为本期涉及的模型、MCP、模型路由、索引/检索设置、仓库连接、通知通道保留可追溯变更。业务发布历史如已满足追溯要求，复用已有记录，不重复建设第二套发布系统。

每条记录至少包括：

- 资源类型、ID、当时显示名称；操作类型；变更前后配置修订。
- 修改时间、操作人或系统任务来源；关联请求/操作标识。
- 实际变更字段及可安全展示的前后值。
- 变化分类：普通维护、行为变化、兼容性变化、审批目标变化、启停/权限变化；允许一条记录含多类变化。
- 批量或隐式联动的关联标识。例如设置新默认模型导致旧默认模型标记变化，两侧记录均能互相定位。

凭据仅记录“已设置/已更换/已清除”及不含密钥的修订标识。连接地址、命令、请求头和其他自由字段应按字段用途脱敏，不得把敏感值写入差异、错误、日志或导出。

只记录成功提交的修改；配置和记录保持一致，失败或并发冲突不得形成虚假成功历史。资源删除后仍保留已发生记录；旧数据无法还原的过去修改不得补造，可建立明确标注的上线基线。

验收：修改温度、地址、密钥、默认标记，均可定位准确差异和操作者；并发编辑冲突不丢失成功变更、不产生失败修改记录；无权限用户不能读取其他用户或管理员专属配置历史。

### RDC-06 运行快照及排查入口（P0）

运行与实际调用记录关联资源 ID、配置修订、业务发布版本、解析时间、执行阶段及脱敏配置快照。快照至少能解释模型/协议/服务目标、有效生成参数，以及本次所用 Skill 内容摘要、工具参数结构、索引兼容信息等实际依赖。

一个运行使用多个模型或多个资源时按实际使用分别记录，不能只存一个顶层模型版本。仅记录已解析/使用的依赖，不把未使用资源伪称为实际调用。失败发生在配置解析阶段时，保留失败阶段和已知信息，不虚构调用。

运行详情提供“本次资源配置”，支持打开对应资源修改历史、比较本次配置与当前配置。历史缺少信息时明确“历史未记录”，不能用当前配置冒充当时配置。快照和历史继续遵守账号、组织、资源及运行的查看权限，不返回凭据。

验收：从一次结果异常的运行可定位当时配置、相关修改和当前差异；多成员、多模型、嵌套流程及恢复后分阶段记录均可区分。

### RDC-07 模型路由按能力和接收方变化检查（P1）

候选模型普通维护不使智能体业务版本失效；每次新运行按最新路由和实际能力选择，并记录选择原因。已有运行固定已选结果，不因普通维护重新路由或中断。

新增候选接收方、修改服务目标或扩大数据范围时，按变化重新确认接收方授权；不连带要求重新发布智能体。名称、凭据更新等不应自动视为新增接收方。路由停用、撤销授权和候选不兼容仍生效。

验收：普通维护无需重发；新接收方未确认时不发送数据；运行记录可解释路由策略和最终选择，不能隐式切换到未授权候选。

### RDC-08 索引按向量兼容信息判定（P1）

文本知识库、长期记忆、图片和视频索引不再以通用模型修订作为索引失效的唯一依据。单独确定向量兼容信息，至少覆盖实际向量模型身份/版本、维度及影响向量的预处理或参数。

更新密钥、显示名称、默认标记不要求重建。仅迁移服务地址且确认向量模型及输出兼容时复用原索引；不能因为维度相同就假定不同模型可互用。无法确定兼容性时给出具体核对项，不默认为兼容。

真正不兼容时明确提示重新索引；已有关键词降级入口继续可用并说明效果影响。只更新重排模型，不要求重建原文本向量，但记录排序行为变化。

验收：普通维护继续使用原向量；更换不兼容向量模型不混查旧向量；同维不同模型也被正确识别；文本、记忆、图片、视频覆盖一致。

### RDC-09 评测证据与发布门禁分离（P1）

历史评测保留当时的文档、检索参数、模型配置及结果，配置更新不删除、不改写旧结果。区分“该实验曾成功”与“该实验能代表当前配置”。

普通维护不使证据失效；文档、模型或检索行为变化时，标明影响及重新评测建议。开启严格质量门禁时，可要求与当前效果配置相关的有效证据；未开启时不因通用修订不同强制阻止发布。

进行中的对比实验固定自己的数据和配置。若来源无法保持一致，明确实验中断及受影响部分，不能把混合配置结果计为同一实验成功。

验收：更新密钥不会使已通过门禁失效；真实行为变化准确标识适用性；严格策略按实际影响判断，旧结果仍可查看比较。

### RDC-10 MCP、Skill 与审批内容分离（P1）

新运行获取当前可用工具定义和 Skill 内容。工具实际存在、启用、参数结构、只读/写入性质、执行环境和能力授权必须校验。Skill 发布更新不自动要求重新发布所有引用它的智能体。

批准记录绑定具体操作目标、命令/脚本内容摘要、参数及必要范围，不绑定无关显示字段。密钥正常轮换不自动改变已批准操作；执行目标、脚本或关键参数发生变化，才重新确认该操作。

验收：普通维护不阻止新运行；旧审批不能执行修改后的脚本、目标或参数；工具只读性质或结构变化时准确拒绝，不误报为整个智能体必须重发。

### RDC-11 仓库任务和成果恢复细分校验（P1）

保留仓库身份、固定源码提交、工作区范围、任务分支、成果摘要及已批准推送内容。显示名称、同一身份的凭据更新不阻止已有任务或成果恢复。

仓库身份、目标分支、源码基础发生变化时，说明差异，按恢复/发布动作重新检查或确认；不得把旧成果静默套用到另一个仓库。

验收：更新凭据后可继续原仓库任务；改目标仓库不能复用旧推送审批；历史源码与成果证据保持可追溯。

### RDC-12 通知通道变更不误伤待发送消息（P1）

通知记录固定接收目标及消息内容，发送时可使用同一目标的最新凭据。名称、凭据更新不使待发送消息失败；目标地址/接收人变化时暂停该待发送记录，提示确认，不自动改投新目标。后续新消息按新目标创建。

确认重发保留原记录与新投递记录的关系；结果未知时不自动重复发送。通道停用、接收权限撤销仍阻止发送。

验收：改名称/凭据可投递；改收件目标不会将旧消息发给新收件方；失败原因和恢复入口明确。

### RDC-13 保留必要的一致性与权限检查（P0）

以下机制不属于应删除的跨资源修订绑定：

- 多人编辑时防止覆盖保存的并发修订检查。
- 账号、资源授权、启停、版本下线、任务取消及执行租约检查。
- 具体写操作的审批参数和执行目标一致性。
- 向量、工具接口、输入输出 Schema 等实际兼容检查。
- 正在执行的一轮会话所引用内容的一致性，以及找回密码、OAuth 等身份凭据流程的有效性检查。

同一错误处理不得把“配置已更新”误写成“权限撤销”。新旧版本比较仍可用于发现变化，但变化后的动作必须依据其真实类别。

### RDC-14 中文交互与错误定位（P0）

复用资源详情及运行详情，不新增独立复杂管理中心：

- 资源详情增加“修改记录”，支持查看字段差异、操作来源和关联运行入口。
- 运行详情增加“本次资源配置”，展示实际采用信息，并可比较当前配置。
- 工作流错误可定位到节点及资源；团队错误可定位到成员。
- 新运行使用更新后的配置无需额外确认；仅在真实兼容或审批边界发生变化时出现相应操作。
- 错误区分资源不可用、能力不支持、索引不兼容、审批内容改变、待确认恢复等原因，给出对应操作。
- 仅通用配置修订发生变化时，不再展示“请重新发布智能体/工作流”或“请新建运行”。

验收：只读账号可在既有授权范围查看追溯信息，无修改入口；窄屏可阅读差异；定位后能返回原运行且不丢失选择状态。

## 5. 旧数据兼容与上线要求

1. 保留现有智能体、工作流、任务、模型配置、密钥和发布历史；不批量重新发布或修改业务定义。
2. 历史 `model_revision`、`resource_pins` 等可作为历史依据，不再直接代表当前不可用；不能用当前值覆盖后伪称历史配置。
3. 分别识别业务版本引用、运行快照、授权依据和向量兼容信息，不能统一删除所有 pins。
4. 旧向量的兼容信息有证据时迁移；证据不足时明确待核对，不为消除错误强行声明兼容。
5. 对上线前已排队、运行中、待审批、暂停的任务分别验证。迁移无法安全衔接时展示明确状态和恢复入口，不能悄悄执行或误报成功。
6. 复用现有审计、运行用量和版本记录，补足缺失的字段差异与快照关联，避免重复业务入口。
7. 数据及结构变更先备份，在隔离环境验证升级与回退。回退方案须考虑新增任务状态和记录，不能仅承诺回退代码。

## 6. 测试与交付门槛

按“需求确认 → 开发文档和影响清单 → 开发自验 → 独立代码审查 → 修复复审 → 测试验收 → 部署”推进。产品需求阶段不视为已授权在本轮直接修改或部署业务功能。

### 6.1 必测场景

1. 原问题回归：模型修订变化后，旧“自动任务助手”发布版仍可创建自动任务。
2. 变更分类：改名称、默认标记、密钥、地址、参数、类型分别产生正确历史和行为。
3. 任务时序：排队前后、首次调用前后、多次调用之间、暂停和重启恢复时更新配置。
4. 团队级联：成员模型变化无需重发父子版本，权限撤销仍有效。
5. 工作流入口一致：只读、Work、外部 API、Agent 工具、嵌套流程以及旧版设为当前。
6. 业务版本独立：回退 v1 不改变其节点逻辑、明确子流程版本或已固定 v2 的调用。
7. 向量兼容：普通维护、兼容地址迁移、不同维度、同维不同模型及重排变更。
8. 审批边界：更新凭据可继续，同一审批不能执行改变后的目标、脚本或关键参数。
9. 追溯完整：多模型、多成员、子流程和恢复阶段均可定位实际使用配置；旧数据不伪造历史。
10. 记录一致：并发冲突、事务失败、隐式默认切换及资源删除后历史保留。
11. 权限及脱敏：跨账号不可见；测试秘密值不能出现在历史、快照、错误、日志及导出中。
12. 原功能回归：取消、停用、版本下线、预算、审批恢复、幂等和并发编辑保护保持有效。

### 6.2 验证证据

- 后端针对新行为及保留边界进行自动化验证，前端覆盖实际追溯和修复操作路径。
- 用受控模型/工具替身验证时序、接口和故障场景，明确其不能证明真实供应商效果。
- 真实外部服务继续遵守用户此前暂缓联调的要求；未验证项单列，不计为通过。
- 验收按 RDC 编号记录结果及证据，不以总测试数量替代需求覆盖，也不承诺系统绝无 Bug。
- 上线记录分支、提交、数据库变更、部署版本和验收结果，复用现有平台发布流程。

## 7. 实施优先级与范围边界

建议分两批实施，但共用同一套语义，不能第一批只移除入口报错、执行阶段仍因旧修订被拦截。

- **第一批 P0**：RDC-01～06、RDC-13～14。先闭环原问题、团队/工作流级联、历史回退、运行配置和追溯。
- **第二批 P1**：RDC-07～12。细分路由、索引、评测、工具审批、仓库及通知的变更处理。
- 任何 P1 中被 P0 共用调用链实际影响的逻辑，须同步做兼容适配，不能留作已知回归。

不在本期范围：历史输出完全复现、自动回滚所有资源配置、密钥历史管理系统、替换现有 Agent 内核、引入新监控平台、扩大 SSE 范围或建设多环境发布平台。

本需求在资源关联语义上替代既有文档中“外部配置修订变化必然要求重新发布”的条款，包括工作流版本文档中的对应资源 pins 限制；草稿保护、业务发布版本不可变、明确版本调用、权限与审批要求继续保留。实施时同步修订相关文档及测试，本文不声称这些同步工作已完成。
