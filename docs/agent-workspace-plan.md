本计划沿用 `development-plan.md`，保留用户现有配置与数据。真实外部模型联调按此前要求暂缓；测试使用隔离数据库和可控协议服务。

1. 运行记录：基于实际持久化的运行和事件，以当前账号隔离查询，展示状态和时间，并可打开所属对话。验证跨账号隔离、排序和浏览器交互。
2. Agent 管理：用户可创建、编辑、启停 Agent，配置模型、系统指令、知识库、MCP、Skills 和联网权限；对话选择 Agent，服务端校验归属并在运行时固定配置快照。验证不同 Agent 的配置生效、越权拒绝和历史运行可追溯。
3. 联网：区分模型原生联网与平台搜索工具，按服务商协议和模型能力明确支持范围；搜索服务在页面配置，密钥加密，用户或 Agent 明确启用后才调用，返回来源并限制超时与数量。验证请求、失败、权限和来源，不假定所有模型均支持原生联网。
4. 任务工作台：依据原方案接入 OpenSandbox、任务持久化、可恢复执行、事件、预算和成果；在沙箱与审批未验收前不得将宿主命令执行暴露给 Agent。
5. 工作流：先实现可校验、可保存、可调试的 Start → LLM → End，随后按原文档扩展节点、版本、审批和发布；只有真实执行、状态保存与权限验证通过后才开放入口。
6. 继续未完成的模型类型接入，参考 `multimodal-integration-plan.md`；真实服务配置与联调继续等待用户准备。

每个阶段完成后运行针对性后端和浏览器测试，记录实际通过项和限制。禁止使用占位页面或模拟响应冒充已完成的真实功能。

## 当前进度

“运行记录”已开放：展示当前账号最近 100 次真实运行，可打开所属对话。服务端通过对话归属过滤；37 项后端测试通过，包含跨账号隔离。浏览器回归 5 项通过，其中运行记录界面使用模拟数据验证显示和跳转；生产构建通过。

智能体管理首版已接入：账号可创建、编辑、启停智能体，配置聊天模型、系统指令及联网开关；新对话选择智能体后固定归属，运行创建时保存名称、指令、模型 ID、版本和联网开关的快照，不保存密钥。已有对话的智能体不能删除，可停用。当前知识库、MCP、Skills 仍沿用账号的通用助手绑定，尚不能按智能体独立选择；模型服务配置本身尚未版本冻结。

联网首版使用 Tavily 搜索工具（不是模型提供商的原生联网功能）。管理员在“智能体管理”配置并启用 Tavily 密钥，智能体单独开启联网后，模型可按需调用搜索并读取标题、链接和摘要；搜索词将发送至 Tavily，服务可能计费。服务端每次调用检查智能体及联网权限，密钥加密且不回显，关闭权限立即生效，结果限制数量并设置超时。模型需要支持工具调用；未配置服务时运行会明确拒绝。Tavily 请求遵循[官方搜索接口](https://docs.tavily.com/documentation/api-reference/endpoint/search)。

本地数据库已应用 `006_agents.sql` 和 `007_web_search.sql`。后端 41 项测试通过，覆盖智能体归属、版本冲突、运行快照、搜索服务管理员权限/加密、工具协议及搜索结果在图内保存；网络使用模拟传输。浏览器验证创建和选择智能体及联网开关，搜索配置页面使用替身，不修改实际密钥。未进行真实 Tavily 或模型联调。

各智能体已支持独立选择知识库、MCP 和 Skills；迁移时旧智能体继承原账号通用绑定。运行保存资源 ID 快照，并在运行开始时重新校验归属；知识库和 MCP 调用时还检查当前绑定，撤销后停止调用。Skills 文本在运行开始时加载到该运行的虚拟文件系统，运行期间的技能绑定变更于下一次运行生效。通用助手继续使用账号自己的通用绑定。43 项后端测试、5 项浏览器测试及生产构建通过；实际模型仍未联调。

## OpenSandbox 本机隔离验证

已下载并对比官方服务版本：`release-1.1.0` 不支持 `publish_host`，测试时将沙箱端口发布到了所有网卡；发现后立即停止测试容器和管理服务并清理测试容器。`release-1.2.0` 实现了绑定选项，但 Docker Desktop 不接受容器服务在 Windows 主机上绑定 Linux 桥接网关地址。改为 Windows 本机运行官方 1.2.0 服务、沙箱端口绑定 `127.0.0.1` 后，实际测试确认端口绑定、默认拒绝外网 IP 和 Docker 网关访问、沙箱内无 Docker socket，另一个临时容器通过 Docker 网关连接执行端口被拒绝，测试沙箱已销毁。该测试只覆盖一个短时沙箱，不代表完整多租户、安全边界、浏览器和并发配额已验收。管理服务目前已停止；工作台仍不开放。配置与认证的可重复部署、任务绑定、审批、文件成果及完整验收仍待实现。

## 模型原生联网实施细化

智能体联网开关开启时可选择现有 Tavily 平台搜索或 OpenAI Responses 原生 `web_search`；原生模式只接受服务商为 OpenAI、协议为 OpenAI 的聊天模型，并需要该模型实际支持 Responses 与联网工具。智能体保存搜索方式，运行时固定快照；平台搜索沿用原有密钥与运行时权限检查，原生搜索由服务商执行，提交请求后无法保证撤销本次服务端搜索。原生模式不需要 Tavily 配置，可能产生模型和搜索费用，搜索词及上下文会发送给 OpenAI。保留服务端搜索引用并在回答中展示可点击来源；真实模型联调继续暂缓。[OpenAI 联网搜索文档](https://developers.openai.com/api/docs/guides/tools-web-search)、[LangChain ChatOpenAI 文档](https://docs.langchain.com/oss/python/integrations/chat/openai)。

## 沙箱生命周期基础实施细化

先实现内部 OpenSandbox 生命周期适配器，不提供用户可调用的任意命令入口：仅允许平台固定镜像、按环境类型分配 CPU/内存与 60 分钟 TTL、默认拒绝出站、不挂载宿主目录，最多两个沙箱且每类最多一个；创建结果不明时保留配额以防资源超限，回收负责销毁远端并释放本地配额。服务地址与管理密钥仅在本地服务端配置。适配器离线契约测试与本机受控沙箱验证通过后，才能继续任务归属、文件路径防逃逸、Worker、审批及 UI。单实例内配额不是跨实例或跨重启的持久租约，恢复与孤儿回收须在任务工作台开放前补齐。

生命周期适配器首版位于 `services/api/app/sandbox_service.py`：固定测试镜像、两类配额、实例内排队、默认拒绝出站、60 分钟 TTL；SDK 已锁定 1.2.0。4 项针对排队、销毁失败、创建取消及创建结果不明的测试通过。Windows 本机管理服务 1.2.0 实测创建 Coding 测试沙箱，执行 `2+2` 得到 4，Docker 检查显示 4 CPU、5 GiB、512 PID 上限、非特权、仅平台内部运行时卷，端口仅绑定 127.0.0.1，随后销毁并停止管理服务。

该阶段仅验证内部适配器；当前镜像不是完整 Coding/Browser 镜像，没有任务归属、资源余量检查、跨进程/重启配额和孤儿回收，也未完成文件安全与审批。SDK 的销毁返回表示已接受终止，底层清理可能继续，因此实例内配额还不是严格的容器同时存活数量上限。不能据此开放工作台执行。

## OpenSandbox 本机服务部署细化

Windows Docker Desktop 使用本机 Python 进程运行 OpenSandbox 1.2.0，管理接口及沙箱映射端口仅监听 127.0.0.1，管理密钥在本机生成并保存在忽略的本地目录；服务进程可访问 Docker 管理接口，任务沙箱不挂载宿主 Docker socket 或用户目录。使用 `dns+nft` 网络隔离，创建时由平台指定默认拒绝出站。提供锁定依赖和显式启动脚本；该服务为后续 Work 执行的基础，不代表任务、审批或跨重启配额已完成。

独立的本机管理服务已提供锁定依赖和 `scripts/start-opensandbox.ps1`。脚本实际启动通过，管理接口无凭证返回 401、监听地址为 127.0.0.1，管理密钥目录限定当前 Windows 用户、SYSTEM 和管理员；使用该服务的适配器实际创建测试容器、执行简单命令并销毁。服务目前运行，但未接入任务执行；上述尚未完成的安全与恢复条件仍适用。

## 任务队列基础（内部）

新增仅供后续 Worker 使用的持久运行队列，入队时按用户和任务修订号校验并保存目标快照；数据库原子认领使用独立租约令牌，多 Worker 不会同时认领同一待执行运行。只有持有未过期令牌的 Worker 才能续租或提交结果；租约过期的运行进入“需要人工核查”，不会自动重复可能已发生副作用的操作。本地数据库已应用 `016_work_queue_runs.sql`。隔离数据库验证了跨账号拒绝、修订冲突、快照、并发认领、续租、过期和完成保护；后端回归 71 项通过，Ruff 检查通过。
