## 首批可执行边界

主 Agent 可选择最多 6 个本人已发布的 Agent 版本作为角色，填写唯一角色名和委派目标。团队保存进主 Agent 配置与发布快照；成员模型、指令、资源、版本均固定，不读取成员之后的草稿。成员不得再包含团队，不允许循环；执行深度先固定为 1，并行最多 2，本轮委派最多 8。团队成员先提供只读研究/分析/审阅，Work 主 Agent 继续走原审批工具；不能借团队绕过写入审批。

成员知识库、技能、MCP、记忆和联网必须是主 Agent 显式资源授权的子集。冻结快照后仍检查当前账号、父 Agent、成员已发布版本及资源授权；下线/撤权阻止后续调用。团队只向子图传递任务描述，避免自动复制整份父上下文。

复用 Deep Agents 的 CompiledSubAgent/SubAgentMiddleware，子图仍使用平台的同一 Harness，不增加第二层模型循环。每次委派持久保存父运行、成员版本、状态与取消请求；状态和事件由有效父租约写入。未知结果不自动重放，运行诊断展示角色状态、独立取消及用量。父取消传递到子任务；成员取消在模型/工具边界生效，已发出的请求不伪称撤回。

账本根据服务端固定的角色/模型标识记录每次调用，不能把不同成员的 Token 都算成父模型；输入粗估和输出预留先在数据库串行预占，防止并行子任务各自拿到全部剩余预算。保留供应商实际用量与未知统计的含义，粗估仍不是精确 tokenizer。

## 顺序和验收

1. 数据迁移、配置/版本校验 → 两账号隔离、过期/下线版本、递归和非子集授权均拒绝，旧 Agent 默认没有团队。
2. Harness、持久委派和共享账本 → 两角色使用不同模型的替身可委派并汇总，预算竞争、成员故障、并发上限与重复委派均有行为测试。
3. Ask/Work 接入与中文编辑/诊断 → 页面保存/发布/刷新保留团队；取消、运行中撤权和检查点恢复不重复执行未知调用。
4. 本机回归、构建、备份迁移与重启 → 记录通过/失败和限制；真实协作质量仍等待外部模型接入。持久批量任务另接阶段 4 调度，不以同步 task 工具冒充已实现批量队列。
