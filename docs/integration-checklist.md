# 用户接入清单与后续真实验收
更新：2026-11-02。当前结果以[统一系统验收记录](system-acceptance-2026-11-02.md)为准；[早期本机验收](acceptance-report.md)和[11月1日交付记录](final-delivery-2026-11-01.md)保留历史证据。

## 怎么使用这份清单

本机可完成的工程测试已先行验收。以下真实接入未发起请求，继续等待你准备好后再测；已有配置不代表已完成真实服务验收。模型、Tavily、MCP 凭证在平台页面保存，不发到聊天、不改为模型配置文件。

你可以分批准备。准备好后告诉我“U01 已接入，显示名称是……”，或“U03 的知识库和资料已准备好”，我再读取该配置并测试。无需一次接入全部服务，也无需重复填写已经保存且仍有效的密钥。

当前已启用、但本轮没有调用真实服务的三份模型：
- deepseek-flash：聊天。
- BAAI/bge-m3：文本向量。
- BAAI/bge-reranker-v2-m3：重排。

先用现有配置确认权限、额度和可用性即可，不要求重新创建。供应商是否实际支持联网、图片、工具和 usage，接入后逐项验证。

## 优先准备

### U01 聊天与 Work 模型【先准备这一项】

入口：设置 → 模型管理；独立 Agent 在智能体管理中绑定模型。

准备：至少一个可用聊天模型的服务商、实际模型 ID、API 基础地址与密钥。Work 必须支持工具调用，并返回完整输入/输出/总 Token 用量。跨模型切换的完整验收还需第二个实际模型；不是当前必须一次准备两份。

接入后测试：小样例连接、多轮与模型切换、流式中断与取消、工具循环、缓存/推理统计及缺失时的提示。再运行一个小型编程任务和一个文件整理任务，审批后执行、暂停/恢复、核对成果与预算。模型自主规划和结果质量单独判定，不用固定响应替身的结果替代。

不必把服务地址填成 /chat/completions；页面保存基础地址。未填聊天最大输出时平台默认 4,096，Work 单次最高 8,192；温度留空才沿用服务默认。

### U02 联网搜索【原生或 Tavily 选一种即可】

原生入口：设置里的模型配置、智能体管理中的联网授权、对话输入框“联网搜索”开关。准备可使用已适配原生搜索的模型/账户权限；可复用 U01 的密钥，不一定需要新账号。已有 deepseek-flash 的搜索权限尚待真实确认。

Tavily 入口：智能体管理 → 联网搜索服务。仅选择 Tavily 时才需要 Tavily API Key；随后给目标 Agent 开启对应联网模式。

接入后测试：真实时效问题、来源链接、开关关闭后不调用、Agent 未授权被拦截、额度/权限错误、超时和取消。应用搜索记录与服务端搜索证据分别核对；“允许搜索”不能当成模型实际执行过搜索。

### U03 真实知识库与向量/重排【已有两份配置可优先复用】

入口：能力中心 → 知识库，选择文本向量模型、可选重排模型；在智能体管理中绑定该库。

准备：确认现有BAAI/bge-m3和BAAI/bge-reranker-v2-m3的真实服务可用；提供一套验收文档副本及至少50道标注问题，包含明确证据、跨文档、版本冲突和无答案。平台已有题集编辑/JSON导入、文档修订与证据标注、持久检索实验和对照入口；也可先提供资料，由我整理。

接入后测试：分块入库、维度一致、召回、重排收益、文档增删与撤权、Ask/Work/Workflow 共享检索、引用位置和无答案拒答。按原计划报告 Recall@10 ≥90%、引用正确率 ≥95%的目标是否达到，不保证配置完成就达标。测试尽量使用专用验收库，不覆盖原库。

注意：历史合成关键词回归存在误召回及阈值取舍，仍需针对真实语料调优；不会把质量问题仅归因于缺少配置。扫描件OCR工程链路已用本机替身和实际PDF渲染验证，真实识别效果另按U04测试。

## 按需要准备

### U04 图片理解与图片对话

入口：设置→模型管理中的聊天/图片理解模型；智能对话上传图片，或知识库中的“扫描件与图片OCR”。独立“图片理解”导航已按用户要求隐藏，不作为当前入口。

准备：实际支持图片协议的模型及几张有标准答案的 PNG/JPEG/WebP 样图。已有聊天模型是否真正支持图片待 U01 后确认，勾选图片能力不改变模型本身。

接入后测试：图文内容真正送入模型、单图/多图问答、历史恢复、仅文本模型拒绝图片；另用带标准文字的图片/扫描PDF测试OCR准确率、页码、人工校对及复杂表格限制。基础上传、鉴权、格式/渲染、OCR草稿/确认、用量与取消已本机验收；真实识别质量未测。

### U05 语音合成、语音识别、音频理解

配置入口：设置 → 对应模型类型。独立“语音合成”页面已按用户要求隐藏；语音合成、识别和音频理解接口仍保留，但当前没有独立可见操作页。需要验收这些能力时使用对应受鉴权接口，不要求用户寻找已隐藏页面。

准备：需要使用的类型各自对应的模型、服务权限；合成还需实际可用音色标识，识别/理解需 WAV/MP3 测试音频及标准转写/答案。不同供应商的音色不能混用；不是必须三种都接。

接入后测试：请求协议、音色和语言、生成音频播放/下载、转写与理解准确性、超限/失败、私有文件访问。当前只验收已适配协议，其他原生协议属于待开发。

### U06 图片生成与视频理解

配置入口：设置 → 图片生成/视频理解模型。独立“图片理解”页面已隐藏，生成和视频理解接口保留；当前这些功能使用受鉴权接口验收，不引导进入已隐藏导航。

准备：实际开通的模型与样例。图片生成需说明服务返回 base64 还是已适配的对象存储 URL；视频理解需符合页面限制的视频与标准答案。当前视频路径以已接入的百炼兼容协议为准。

接入后测试：真实生成/理解结果、文件持久化、播放/下载或预览、访问权限和错误提示。未知下载域名或其他视频原生协议不能仅靠填写配置变为支持，需要我补适配。

### U07 多模态向量与图文检索

入口：设置 → 多模态向量模型，接口选择项目已接入的百炼原生多模态向量；能力中心绑定到相应知识库。

准备：实际支持该协议的服务、模型/密钥与有标准匹配关系的图片/文字样例。

接入后测试：真实图文向量、维度一致、持久索引、文字找图/图片检索效果、来源与归属、停用和删除。其他服务商原生多模态向量接口仍需开发，不能用一个通用 OpenAI 标签替代。

### U08 实际 MCP 服务

入口：管理员在能力中心 → MCP 添加服务；目标用户/Agent 绑定并选择允许的工具。

准备：Streamable HTTP 地址、如需认证则填写 Token、工具用途与读写标注，以及可以操作的测试对象。先给只读工具即可；写工具只用明确授权的测试环境。

接入后测试：工具发现、调用、参数与结果、认证失效、超时、资源撤权；Ask 不获得写工具，Work 写调用经过审批并保存结果状态。模型是否正确选工具待 U01 可用后验证。

stdio、旧 SSE、OAuth 尚未接入，不要求你先准备这些凭证来解锁本轮验收；它们是开发事项。

### U09 自有 Skills、业务工作流与网站【可选】

入口：能力中心导入 Skills；工作流页面配置/发布；任务工作台选择环境与授权域名。

准备：你的技能包、期望流程与结果，若涉及外部业务再提供测试域名和测试账号。无需替换系统现有样例；公共示例网站浏览与本地脚本执行已有真实本机验证。

接入后测试：技能按授权读取、脚本经审批执行、业务节点输入输出、发布版本固定、实际页面操作与成果。需要写入外部系统时先明确测试对象与可操作范围。浏览器跨组同页操作、实时视图、人工接管和任务隔离登录已完成本机验收；真实网站另按U13验证，不把本机页面成功当作所有网站均可登录。

### U10 费用估算单价【需要金额时再准备】

入口：运营管理 → 设置模型估算单价。

准备：实际模型的输入/输出每百万 Token 单价与币种；已有单价可复用。未提供价格时显示未计价，不显示免费。

接入后测试：真实 usage 对照、币种区分、调用开始时单价快照、修改单价不回算历史。本入口的简单双价仅作历史估算；缓存读取/写入独立计价和金额预算已经实现，请使用U15的“费用与预算”正式价格版本。搜索/多模态额外费用及完整账单对账仍是本轮扩展需求，不与已实现的缓存计价混淆。

### U11 官方 LangGraph 开发服务协议基准【可选，不影响当前平台使用】

准备：仅在要做这项基准时提供 LangSmith 账户接入及官方当前要求的开发标识/凭证，交由我按官方流程配置独立开发环境；不是模型配置，也不是当前平台运行必需项。

接入后测试：官方本地服务、线程、流式事件和中断恢复与平台适配的差异，仅用测试样例，不自动发送生产对话。[官方本地服务说明](https://docs.langchain.com/oss/python/langgraph/local-server)。

### U12 自动任务消息通道【需要外部通知时准备】

入口：自动任务 → 通知 → 消息通道。支持本人签名 Webhook、飞书/Lark、企业微信和 Slack；地址和密钥在页面填写并加密保存，不发到聊天或提示词。

准备：指定实际目标群/接收器，在平台保存通道；飞书按机器人安全配置填写签名密钥，签名 Webhook 与接收端约定密钥。明确允许向这个目标发送一条验收消息后，再做真实发送验证；不购买服务，不向未指定的群发送测试。

接入后测试：真实接收、服务商错误、撤销通道、修改地址后的修订保护、未知结果不自动重发。当前已用真实本机接收器核对四类协议及签名；“渠道已接收”仅代表接口接受，不代表收件人阅读。签名事件入口同时需调用端提供唯一 event_id、正确时钟和 HMAC，不允许用事件数据更改模型、权限或预算。

### U13 真实网站登录与人工接管【有浏览器业务时准备】

入口：任务工作台 → 浏览器环境 → 明确授权网站域名；由任务打开页面，先暂停，再接管完成登录。密码只在接管界面输入，不发到聊天或模型上下文。登录状态仅在本人同一任务中加密保存，可在界面清除。

准备：测试网站域名、测试账号，以及允许操作的页面和提交范围。跨域登录要明确所需登录域名；验证码或多因素验证由本人完成，不尝试绕过网站限制。

接入后测试：实际站点跨操作组保留登录、暂停接管/恢复互斥、环境过期后的重新登录、退出/清除、未确认提交不重复。暂不使用真实支付、生产表单或未明确授权的写入作为测试；本机测试网站已通过，不表示网站风控、硬件认证均已适配。

### U14 GitHub真实仓库、分支/草稿PR与CI【使用仓库开发时准备】

入口：代码仓库 → 添加仓库，填写组织名/仓库名、基准分支和可选代码子目录。令牌只在此页面填写，留空编辑保留原值；公开仓库只读可不填。管理员可分配仓库查看、配置、任务使用和发布权限，私有连接仍按本人账号隔离。

准备：先使用可丢弃的测试仓库。读取至少需要目标仓库内容只读权限；确需发布任务分支时才准备内容写入权限，创建草稿PR另需拉取请求写入，CI检查按目标服务开放只读权限。可以先只读检出，后续在新任务中启用写入配置；连接修订改变后旧任务不会悄悄改用新凭证。

接入后测试：实际读取固定SHA/所选子目录、本人审批测试命令、审阅文件差异与删除/文件模式，再分别批准新任务分支和草稿PR。只对用户指定的测试仓库执行具体批准动作，不向本项目自动提交/推送，不覆盖默认分支或自动合并。核对实际Issue/CI证据持久记录、权限撤销、基准前移和未知结果只读核查。

当前已验证真实本机Git对象、任务环境、单次代码审批、bundle/工作区恢复与本机协议替身；没有连接真实GitHub账号。源码上限180文件/20MB、单文件1MB，可用子目录缩小范围；不自动下载子模块或LFS内容，不把本地初始快照伪称完整上游历史。

### U15 真实价格、缓存明细与金额预算【启用费用预算前准备】

入口：运营管理 → 费用与预算。为所用聊天、向量和重排模型新增价格版本，填写每百万Token的币种、输入/输出及缓存读写规则、来源和生效时间，再设置个人周期预算。旧的简单双价仅作为历史估算；启用金额预算需要正式的价格版本。

准备：服务商官方价格或合同约定、一个可核对的测试账单/用量明细、允许的测试消耗。不要把密钥写入价格来源。CNY/USD分别设置，系统不自动换汇；图像、音视频、搜索等额外服务费用需要另核对。

接入后测试：普通输入、缓存读取/写入、输出/推理细分、服务商不报告用量、实际超额和未知金额核对。当前并发占款、重复/迟到回调、价格固定和未知冻结已有本机替身证据；真实供应商账单一致性仍未验收。

### U16 多服务商路由与原生联网/图片/工具能力【使用备用模型前准备】

入口：设置 → 模型管理中按官方能力声明工具和图片支持；模型路由中配置主模型、有序备用、能力条件与冷却，再由实际使用者逐项确认候选接收方。随后在对话、任务、智能体或工作流节点开启。改地址、候选或修订后需要重新确认；发布的智能体需要重新发布。

准备：每个候选可用的模型配置、允许发送上下文的服务商范围、图片/工具/联网测试样例，以及最低限度测试额度。真实密钥仍只填在平台页面。不能将“OpenAI兼容”当作所有模型都支持工具或原生联网。

接入后测试：实际选择和用量模型一致、原生联网引用、图片与工具能力、冷却后恢复和执行中撤销。当前本机协议替身已验证发送后断流不转发到备用服务；真实跨供应商效果与费用仍待接入。

## 不属于待你接入的事项

Ask持久Worker、受限已发布工作流工具、账号治理、记忆治理、文档增量/OCR工程、评测题集/实验、回答反馈、浏览器工作台、会话分支、持久工作流审批/代码和Git协作工程已经实现。阶段八路由、离线Tokenizer/校准、缓存独立计价、金额预留和定时运营也已实现。2026-11-01的417项后端、37项Chrome是历史批次；2026-11-02最新统一回归为完整后端458项通过，默认79项页面库存最终77通过、2项按要求隐藏跳过，并完成实际审批/Ask重启及备份/Git隔离恢复，详细复测和未验边界以统一验收记录为准，不累加历史次数。真实效果与账单继续按上述U01–U16逐项验证；不能把本机替身结果当作真实服务通过。更多MCP传输、SSO/MFA/OAuth等现已由用户纳入本轮扩展需求，开发与验收以platform-expansion系列文档为准，不要求用户先提供这些凭证来解锁工程开发。静态警告和检索质量不足不要求你通过购买或配置服务“解决”。

## 接入后的验收流程

1. 你确认某项已准备好，并给出平台内显示名称/知识库名称及预期用途；不发送明文密钥。
2. 我先执行该项最小样例，核对权限、协议与消耗；失败则记录具体原因。
3. 通过后再测完整业务流程、失效与权限边界，并保留脱敏证据。
4. 更新本清单和验收报告，将这一项从“待接入/待真实联调”改为实际通过或未通过；不自动代表其他模型和服务商也通过。
