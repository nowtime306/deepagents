## 使用脚本

现有 `scripts/start-platform.ps1` 用于本地全平台初始化，网页部分运行 `next dev --webpack`，只在3100端口空闲时启动，并不重新部署生产构建。API/Ask/Work/Ops已有受管脚本，本次保持运行。

本次增加 `scripts/deploy-knowledge-ui.ps1`，复用既有服务控制锁和 `.local/web.pid`、`web.log`、`web-error.log`。执行命令：

```powershell
Set-Location D:\project\my_agent\deepagents
& .\scripts\deploy-knowledge-ui.ps1
```

脚本先检查分支、已安装依赖和API就绪，再使用现有TypeScript兼容入口完成类型检查。类型失败不停止现有服务。确认3100监听PID与记录一致、进程属于本项目Next入口且命令指向3100后才停止网页；陌生进程或端口占用直接失败。

停止网页后，在同一PowerShell中用 `Move-Item -LiteralPath` 将旧 `.next` 移至本项目 `.local/knowledge-web-previous-时间-随机标识`，构建新产物，再隐藏启动 `next start --hostname 127.0.0.1 --port 3100`。移动前分别核对源和目标的解析后绝对路径均在项目工作区内；不递归删除，不覆盖已有目录。等网页返回200且包含知行标题后才报告成功，保留旧构建与 `.local/knowledge-ui-release.json` 以供回退。

## 失败和回滚边界

- 构建或新网页就绪失败时，脚本只停止归属已确认的新网页，把失败构建移到独立 `.local/knowledge-web-failed-*`，恢复旧 `.next` 并重新启动，通过相同网页检查后仍返回原部署错误；不得把自动恢复当作新版本部署成功。
- 若首次运行没有旧 `.next`，没有可恢复的旧生产包；脚本报告失败，保留错误日志和失败产物，由开发修复后重跑。没有构建备份时不承诺自动恢复。
- 若端口被其他进程占用或回退无法启动，脚本直接报错，不强行结束其他应用。先看 `.local/knowledge-ui-build.log` 和 `web-error.log`，报告故障，不启动重复实例。
- 成功后保留的备份只包括旧前端构建，不包括数据库、`public`资源、源文件或依赖。后续人工回退必须由执行者确认目标备份、停止同一归属网页、校验全部绝对路径后把当前 `.next` 移到另一独立本地目录、将备份恢复到 `.next`，再按上述生产启动命令隐藏启动并检查200。若后续涉及依赖/公共资源/API变化，需要相应版本一并回退，不能仅恢复 `.next`。
- 每次成功保留一份唯一备份，不自动轮转或删除；磁盘清理应单独核对保留范围。本批无数据库变更，不做数据库回滚。
