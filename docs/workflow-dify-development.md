# Dify 参考工作流开发计划

依据 workflow-dify-requirements.md 的 WF-D01～08，2026-11-03 开始。先冻结需求，再后端/前端并行，作者自验、独立审查、QA、既有部署脚本发布。保留当前数据、schema_version=1、同步 HTTP200 和工作流查询方式，仅智能对话使用本轮 SSE。无新依赖、迁移或常驻服务，不提交推送。

## 顺序与分工

1. 后端：只读配置诊断接口；复用严格验证的节点参数和支配关系；转换节点新增受限模板及单节点显式变量语义。验证：隔离库正常/失败/无权限/无运行副作用、完整运行/预览/发布/Work 与旧定义。
2. 前端：五种自包含模板、可搜索分组节点库、上游变量选择、配置检查定位、模板配置、变量检查与明确复用、撤销重做/有界拓扑整理。验证：纯算法与组件作者自验，类型/静态检查。
3. 独立审查后 QA：依据 workflow-dify-tests.md，独立库和生产构建浏览器操作；原有工作流、节点调试、修订/发布边界及 Ask SSE 定向回归。真实外部模型继续跳过。
4. 发布：已有脚本备份当前状态、生产构建及重启；检查健康、监控和用户数据/主密钥摘要；精确清理测试资源。

## 前端实现边界

- workflow-design.ts：模板定义、必经上游选择、模板引用提取和有界布局；只操作配置，不执行用户表达式。
- workflow-editor：复用 React Flow，搜索分组、变量插入、JSON取值试样；定位请求只移动视口与选择节点。旧合法开始输出引用保留，不静默重绑无效来源。
- workflows：检查 POST /workflows/validate，body={definition}，返回 valid/scope=configuration/issues[{code,node_id,field,message}]；不自动保存、不启动执行。检查结果以当前配置标识绑定，迟到结果不得覆盖新流程。
- workflow-variables：来自当前真实运行与节点事件，显示来源/状态/输入输出；复用仅同修订且无未保存语义修改的节点输入，仍需显式测试。不修改旧运行、不自动调用上游。
- 编辑历史：当前会话最多40个完整图/布局快照，复合节点操作只记一个修改前快照；新编辑清空重做。只读/运行中禁止操作，输入区域保留原生撤销；切换流程清空。

开发顺序是依赖顺序，不是完成声明。预计分成核心数据能力、编辑工作台、审查验收三批；各批以实际检查通过为准，不以固定时间替代质量门槛。交付报告记录实际结果与未测外部服务。
