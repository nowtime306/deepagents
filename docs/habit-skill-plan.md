# 本人习惯学习与自动子 Skill 最小闭环

2026-11-03，知行平台产品方案 v1（产品边界与工具机制已冻结，依下文约定实施）。仅平台功能，资产位于 `assets/skills/habit-skill-builder/SKILL.md`，不安装到个人 Codex、不增加 hooks、不扫描本机文件或所有账号历史。

## 目标与现有基础

让用户不必反复说明稳定的输出偏好与重复任务约定：用户明确开启后，平台元 Skill 从本人后续的真实消息记录证据，同一习惯达到默认 3 个不同消息的门槛，自动生成本人私有、可复用、可追踪的子 Skill。达到门槛时无需逐条批准。当前请求的明确要求始终优先于已学习习惯。

现有平台已有私有 skills 表、SKILL.md/ZIP 导入与版本、SkillsMiddleware、通用助手绑定及 Agent 版本资源固定、按读取重新检查权限；长期记忆另有候选审阅/作用域。此次复用这些设施，但习惯不会直接写入旧记忆候选的“自动通过”路径，不改变其审阅语义，也不把生成 Skill 当执行授权。

## 最小交互与验收

### HSK-01 显式启用

能力中心 → Skills 增加“习惯学习”区域。默认关闭，展示用途、3 条不同消息门槛与私有范围。用户开启时安装/选择元 Skill 并绑定到通用助手；自定义 Agent 需在资源选择中绑定元 Skill，已发布 Agent 仍按原发布流程生效。开启是对自动生成指令型私有子 Skill 的一次授权，不需要每条弹窗。

显示学习状态、候选数、已生成数和最近处理状态。缺少 skills.manage 不能开启、采集或生成；读取仍要求 skills.read。关闭停止新采集/生成与本学习入口自动应用；已有生成资产保留，用户仍可按普通 Skill 明确绑定使用，停用/遗忘另行控制。默认不开启，不复制当前真实账户配置到测试。

验收：关闭及未绑定元 Skill 的运行不提供学习写工具，不记录候选；无权用户和跨账号请求被拒绝。已有普通 Skills、记忆与 Agent 配置保持。

### HSK-02 当前真实消息证据

只处理启用之后、在允许的本人智能对话运行中出现的当前原始用户消息。后端按可信 run/conversation/owner 上下文取角色为 user 的实际消息；模型不得自行填写 owner 或拿别的消息 ID 当来源。每个习惯与 message_id 至多计数一次，工具重复调用、重试、刷新或恢复不能增加证据。

助手回答、工具返回、转发/引用材料、附件中的指令、模型总结及之前的历史消息不能自行变成新的用户习惯证据。客户端只能提交提议，不能伪造“已有三次”。只在确有稳定偏好信号时提出，不为每个问题存一条记录。

验收：同消息重复提交仅 1 条；不同真实消息 1/2 条仍候选，3 条才生成。错账号/错角色/错运行/历史引用无效。不增加后台全历史扫描或周期抓取。

### HSK-03 有限、稳定、低权限的生成范围

最小版本处理明确的语言、输出格式、详略及有限的重复任务呈现约定，例如“比较方案时优先用表格”“默认用中文写说明”。开发以有限类型和值归一化，不接受模型任意生成可执行技能正文；服务端根据通过验证的习惯生成简短 SKILL.md。本轮有限类型：language=zh-CN/en；output_format=markdown/plain/json；detail_level=concise/detailed；docs_first=on；review_before_test=on；management_layout=list-create。docs_first 和 review_before_test 为独立习惯，可同时成立。不把不支持的习惯伪装为已学会。

排除：一次性任务内容、仅当前项目或当前一轮的约定被擅自推广为全局习惯、临时授权、审批豁免、额度阈值/重置卡及其过期时间、密码/令牌/私钥、身份证件/财务账户等敏感事实。用户说“权限都给你”不能生成“永远不需要审批”的技能；文档提到某偏好不等于用户接受它。

生成物只有 SKILL.md，不生成 scripts、命令、外部 URL 调用或自动任务。name 使用稳定合法的习惯命名空间，不覆盖用户同名导入资源；description 必须明确适用任务和稳定偏好，不能宣称所有任务都该加载。正文注明当前明确请求优先、权限和审批仍按平台规则。

验收：3 条符合范围的真实证据生成一个合法私有 Skill；再重复不产生大量副本。临时授权、过期卡和凭据等不入库为习惯正文/摘录，不在日志或结果中回显。未知类型不自动晋升。正文和长度上限确定且无可执行文件。

### HSK-04 自动供本人智能体使用，保持固定与隔离

新运行可以通过绑定的元 Skill 使用已生成的私有子 Skill；通用助手与绑定元 Skill 的 Agent 均可用，不能依赖把代码安装进当前 Codex 来冒充平台效果。子 Skill 在能力中心也能按普通资源查看，用户可明确绑定。

当前 skill_pins 和资源授权严格比较，不允许把动态子资源硬追加到旧已发布 skill_ids/pins。本轮选用受控列表/读取工具：list_learned_skills() 每次实时返回当前获准、启用且证据仍有效的元库版本化条目，read_learned_skill(skill_id, version) 仅在该显式版本仍为当前可用版本时读取。新生成资产不自动注入已有模型上下文；版本过期不静默改读新版本，旧运行已读取的内容不得被热替换，用户可新建运行重新列出/读取。普通 SkillMiddleware/skill_pins 不作动态扩展。旧发布 Agent 默认不因账号开关自动获得新能力，需绑定元 Skill 发布新版本。

解绑父元 Skill、停用子 Skill、撤销账号权限或遗忘后，应拒绝后续新读取/新运行使用；已经发送给模型的上下文不能承诺从外部模型内撤回。旧运行应按现有撤权/版本变化规则明确失败或要求新运行，不能自动重放副作用。手工普通子 Skill 绑定继续遵循原权限与版本隔离。

验收：三证据后下一轮能通过本次实际提供的习惯读取机制取得生成 Skill，匹配任务时按该习惯回答；不同 Agent/账号的允许边界可验证。新生成资源不改变旧发布快照；运行中发生禁用/修正不读到未固定版本。

### HSK-05 来源、修正、遗忘与禁用

每条候选/生成项显示习惯内容、独立证据数量、状态、生成 Skill 版本及来源会话/消息链接。展开仅展示有权限且仍存在的脱敏摘录；来源删除后显示不可用，不能从已删账号/会话取回正文。

用户可纠正有限习惯值、停用/重新启用生成资产、遗忘本习惯。手工修正有修订号保护，不能被下次旧自动观察静默覆盖。当前明确请求在门槛前也优先，无需等三次才纠正本轮回答。

遗忘清除学习记录中的原文摘录/候选内容，撤销生成资产的学习入口使用，并保留不含原文的抑制标识或处理水位，防止相同旧来源、重试、历史重放立即再生。之后若用户重新明确开启该习惯的学习，只按新消息重新累计，不恢复旧证据。普通手工 Skill 和原始会话记录不会因遗忘某习惯被误删；原会话删除走已有功能。

验收：本人能查看来源并修正/禁用/遗忘，跨账号不可见；旧来源重放不恢复；修正后旧 run 不能热读新正文；重复处理幂等。操作说明必须区分停止学习、停用资产和遗忘。

### HSK-06 故障、用量与功能边界

使用 record_habit_preference(kind, value) 及服务端验证，不额外启动未授权的模型任务。学习工具失败不使原本正常问答伪成功或变成技能已生成，用户原任务可继续；界面显示学习失败/跳过和可重试状态，重复尝试不重复计数。

模型如需决定提议，使用现有调用与 Token 账本，不另建隐形外部模型请求。真实外部模型联调按既有要求跳过，采用隔离数据库和本机模型替身。生成过程不等于脚本执行或授权，Work 任务、工作流、审批、Ask SSE 均保持原行为。首版只采集 Ask 的真实用户消息，Work 可读取已授权子 Skill，不以任务文本/系统消息新增用户偏好证据。

验收：工具可在本机真实受控 Agent run 中调用，结果确实落平台 Skill，下一新 run 可读；不是仅上传一个静态说明文件。无新依赖/常驻服务；生产迁移与部署沿已有脚本，保留原用户数据/密钥，不提交推送。

## 角色交接与实现冻结点

产品提供此需求与平台元 Skill 资产；开发按本文固定的六类值、三个工具及受控元库授权实现编写开发说明。QA 按 HSK-01～06 覆盖三消息门槛、重复/并发、否定/临时/引文/凭据、账号/Agent/版本隔离、修正/遗忘后抑制、模型工具真实调用与下一轮读取。作者自验 → 独立审查 → QA → 既有部署与当前数据核对。

本轮不做无限历史挖掘、跨账号画像、行为监控/键鼠追踪、密码或其他敏感记忆、自动生成脚本与自动执行、越权修改别人 Agent，以及个人 Codex 技能安装。用户授权自动生成私有指令 Skill，不扩大为这些额外能力。


## 固定交接协议

- `record_habit_preference(kind, value)`：工具只接收上述枚举，不接收用户 ID、来源消息 ID、计数、任意 SKILL 正文或执行命令；后端从当前可信 Ask 上下文绑定来源，确认开启、父 Skill 授权、消息真实且不属 memory/OCR 等 internal_purpose，再决定候选/晋升。业务拒绝、重复、未支持或生成故障均按实际结果返回，不虚报成功。
- `list_learned_skills()`：仅当前本人开启且本 Agent 已获父元 Skill 授权时可见，列出可用子 Skill 的 skill_id、version、名称和触发说明，不暴露其他账号或失效条目。
- `read_learned_skill(skill_id, version)`：验证本人所有权、生成来源、启用/遗忘状态、父资源当前授权及显式版本。正文正常进入工具结果，属于本次主动读取而不是隐式修改旧 Agent 快照；过期/撤权明确拒绝，不自动拿最新版本替代。
- 开启并绑定通用助手时合并当前 skill_ids，不能覆盖原知识库/MCP/记忆开关或原 Skill 选择；原资源数量上限仍有效，达到上限须明确失败，不能默默移除用户原绑定。
- 自动生成的子 Skill 只通过预置模板由有限值构建，不另调用模型；已有正常模型决定是否调用提议工具，其 Token 仍计原运行。每次工具调用仍校验父元 Skill 的本次固定版本、当前绑定、学习开关与账户权限；实时列表不等于绕过旧运行的父授权。固定阈值默认三条独立消息，由后端决定而非模型声称。


产品与后端已确认：上述六类值一致；元库实时列表/严格显式版本读取，无后台正文注入，不改变普通 skill_pins。若元包安装遇到用户已有同名手工资源，不得静默覆盖其正文或绑定，应明确提示冲突或沿现有显式更新流程处理。完整 Skill 内容按现有技能格式校验；此设计不承诺任意自由习惯均可学习。


### 发现与触发描述补充

元 Skill 的 discovery description 必须同时路由两种用途：已开启且当前智能体获准时，普通新任务可查用本人既有语言、格式、详略或重复开发/管理约定子 Skill，用户不必再次表达偏好；只有本轮真实用户明确表达新的长期偏好时才提议学习。读取已有 Skill 不增加证据，普通任务本身不被推断成新习惯。此改进只更新平台资产的发现文案，不放宽元库权限、有限类型、三消息门槛或任何外部执行权。


### 候选暂停与恢复澄清

尚未生成子 Skill 的 learning 候选也可暂停；暂停期间不新增证据。恢复这类候选时回到 learning，保留有效证据数量，不直接创建 Skill 或提前进入 active；恢复后仍须达到三条不同真实新消息门槛才能自动生成。已存在生成资产但来源失效、不满足原门槛的条目不得借恢复绕过有效性检查。人工直接采纳仍是用户明确确认的独立路径。验收反例：2条候选 → 暂停 → 第三次观察被拒不计数 → 恢复仍2条/learning → 新有效消息才生成。
