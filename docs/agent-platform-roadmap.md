## 阶段 1：知识证据与会话工作空间（本次首先实施）

### 1A. 检索证据与无答案保护

- 排除仅由中文单字或常见问句产生的弱匹配，保留明确词组、编号和关键词；不能通过屏蔽所有结果刷高无答案指标。
- 区分候选召回、证据筛选、重排结果和服务降级；保留文档、分块、位置及各自分数含义。
- 检索无有效证据时返回明确的无证据状态；工具提示模型说明资料不足，禁止把检索空结果编造成有出处的回答。此规则不宣称能确定性保证生成模型拒答。
- 保护已有向量、混合召回及重排路径，不用关键词门槛强行删除纯语义向量结果。
- 在知识库检索测试页展示证据状态、筛除数量与降级提示。

验收：50 题合成集同时保持有答案召回并改善无答案检索；补充中文弱匹配、编号、英文、混合检索、重排失败和权限回归。实际向量与生成引用/拒答继续待联调；报告前后结果和限制。

### 1B. ChatGPT 风格的会话管理

- 增加本人私有项目：新建、重命名、删除空项目或将会话移出；项目删除不得删除会话。
- 对话可加入/移出项目、置顶、按标题和消息搜索；后端过滤和分页，搜索不读取其他账号的消息。
- 侧栏保留新建对话、近期/归档切换；项目和搜索占用较少空间，操作收进菜单。
- 将原生 prompt/confirm 改为中文可访问弹窗，保留删除/归档运行中限制。
- 桌面会话居中、手机可收起侧栏；标题和长内容不能挤出视口；加载、空结果、失败均有反馈。

验收：新建项目→创建/移动会话→搜索正文→置顶→归档恢复→删除项目后历史仍在；两个账号互不可见；搜索特殊字符、分页、并发运行和窄屏通过。旧会话默认没有项目，迁移不修改旧标题或消息。

## 阶段 2：持久 Ask 与 Harness 收敛

- Ask 从 API 内存任务迁移到持久队列，使用租约、心跳、取消和恢复；复用 Work 的成熟边界，不重复实现调度体系。
- 保存运行策略、模型配置修订、预算和已完成工具证据；恢复时重新授权。
- 模型请求/写入工具结果未知时不自动重放；需要明确的新一轮恢复动作。
- 上下文组成、压缩事件和重复工具无进展可视化；在有副作用前停止失控调用。

验收：强杀 API/Worker、租约过期、多 Worker 竞争、连续取消、重复事件、未知结果均有测试；历史消息兼容，费用不重复入账。

## 阶段 3：可配置多 Agent 团队

- 界面配置角色、目标、模型、资源和团队成员；固定发布快照，运行时不受后续编辑影响。
- 主 Agent 按任务委派；先提供有上限的并行独立子任务与汇总；共享父预算，限制嵌套深度和总委派数。
- 子 Agent 资源只能取显式授权范围；Ask 团队仍只读；审阅者不能替代真正测试证据。
- 展示父子调用、各角色 Token、进度、失败和独立取消；批量任务使用持久租约。

验收：资源撤权、循环委派、总预算竞争、角色故障、取消传播和跨重启；确定性替身验证调度，真实协作质量待模型联调。

## 阶段 4：主动任务与通知

- 先实现一次性和固定间隔，再增加有时区预览的 Cron；发布版本固定，默认关闭自动写操作。
- 触发记录与任务入队同事务，事件幂等；定义错过执行、忙碌排队、重启补偿和重复触发策略。
- 先提供平台内通知和历史，随后按需增加签名 Webhook、飞书/企微/Slack 连接器及用户映射。
- 自动任务仍执行运行授权、审批、预算和取消，不以定时任务身份扩大权限。

验收：时区/夏令时、停机恢复、多实例竞争、重复事件、撤权、通知失败隔离。外部消息渠道接入列为待用户配置。

## 阶段 5：自动记忆与知识运营

- 从用户授权的会话生成可审阅记忆候选，显示来源；确认后生效，支持拒绝、编辑、去重、冲突和到期。
- 语义召回按账号/项目/Agent 授权过滤；原始外部资料不能直接成为持久系统指令。
- 文档处理补分块策略、增量更新和逐文档状态；OCR/复杂表格按真实需求引入受限解析服务。
- 评测数据集、检索实验对照、证据标注和回答反馈持久化；无答案、过期、冲突、扫描件分别统计。

验收：记忆来源和删除可追溯、跨账号不可召回、冲突不静默覆盖；真实 50 题 Recall@10 ≥90%、引用正确率 ≥95%，另报无答案拒答和成本，指标未测不填零。

## 阶段 6：工作流、项目成果与浏览器

- 结构化输入输出和表单校验；有上限的循环/迭代、并行汇聚、错误分支、人工审批、受控代码和子工作流，逐类验收后开放。
- Ask 仅允许通过只读审计的已发布工作流；继承预算/取消，不能绕过 HTTP/MCP 写入限制。
- 会话分支、编辑问题后另开分支、授权引用；旧分支和已发生外部操作不被伪造撤销。
- 成果预览、差异和下载；网页实时视图、用户接管及按任务隔离的持续登录状态。

验收：分支历史不丢失；流程最大步数、父子预算、审批恢复可证明；浏览器接管不绕过审批，私有文件/登录状态不串号。

## 阶段 7：开发任务与 Git 协作

- 仓库绑定、受限克隆、任务分支/工作区、代码差异审阅和测试证据。
- 用户显式授权后才推送/开 PR；Issue/CI 反馈进入可追溯任务历史。
- 凭证通过受控代理使用，不写入模型上下文或成果；未知推送结果不能盲目重试。

验收：使用本地临时仓库验证分支/冲突/路径/凭证边界，再按用户授权联调实际 Git 服务；不得在本项目自动提交或推送。

## 阶段 8：模型、账号与运营

- 定时备份、轮转、容量告警、隔离恢复演练、多实例与并发验证。

验收：改密撤销旧会话、降级无副作用重放、预算竞争不超预留；恢复验证真实附件和凭证，容量结论附环境与并发数。
