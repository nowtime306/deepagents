# 浏览器录制技能界面实施与体验修复

依据主工作区的 agent-platform-optimization-requirements.md（BSK-01～09）及 platform-ux-experience.md（UX-01/02）。2026-11-03，本分支 `onwer_agent_browser_skill`，基于平台基线2818e6f；未部署。

## 页面与操作

能力中心→Skills分为技能库/习惯学习与浏览器录制，录制页面以列表＋新增弹窗为入口。列表展示安全站点、步骤、状态、修订、更新时间，详情展示全部步骤及发布阻断原因。管理员才检查本机连接及新增/控制；本人资源的读取、参数维护和发布仍受原权限控制。

新增异步返回只表示starting，页面按生命周期查询，不能提前显示正在录制；停止后审阅，填写场景及参数名/说明，保存CAS草稿，再单独发布。原始输入不展示、不作默认值。发布后的skill_id派生“已发布”，不可再编辑录制草稿；有真实技能查看入口，不自动绑定。删除录制保留已发布技能。

修改后返回列表、切换技能视图/能力标签或新增录制前确认丢弃；409保留当前编辑。请求成功后的读取失败说明已完成，避免误导重复提交。列表/详情使用独立请求序号，迟到结果不能覆盖已选择记录。

## Work授权与审批

Work的新运行增加管理员专用的“允许本次使用本机已登录浏览器”，默认关闭。切换环境及成功提交后复位；恢复副本也必须重新勾选。仅browser环境向StartWork提交true，不在Task/Agent持久默认授予能力。后端仍独立校验。

审批读取本人固定Skill的trajectory.json，校验真实名称、启用状态、版本、步骤数、参数集、动作和阻断标记。未读到或不匹配时不允许批准，拒绝始终可用。完整路径与运行参数展示后，一次批准整条固定路径，digest和参数绑定；不宣称每次点击单独人工审批。说明使用已登录账号、没有网络硬隔离、域名仅约束顶层导航。

## 实际体验修复

- UX-01：只修改知识库检索显示。命中保留原文、来源、分数，增加分数不是回答置信度的说明；零命中沿原空态引导。不显示专供模型的guidance，后端响应及工具约束保留。

## 验证与边界

开发顺序：接口合同→列表/录制→参数发布→任务显式授权→真实审批路径→独立审查→隔离页面/API验收→部署。各步通过证据分别记录，不把构建当作页面验收。

作者已完成TypeScript检查及一次webpack生产构建；共享只读node_modules的worktree不满足Turbopack目录边界，因此沿隔离基线站已有方式用webpack构建，未改变生产配置。后续源码修改需再构建最终版本。新增UI尚待真实页面测试，真实外部模型调用继续跳过。
