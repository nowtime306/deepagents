# 本人会话的授权引用实施计划

2026-11-01，onwer_agent，阶段六后续。当前已有独立分支/附件复制；本项用于在当前对话显式引用其他本人会话的正文，不自动合并历史、模型账本或来源智能体权限。先保存设计，待前一批完整验收后实施。

## 行为与边界

- 当前会话中显式选择最多3个本人来源；每个来源固定最近最多20条已完成的用户/助手正文，总计最多32000字符。提供来源标题、条数和更新/移除；不将工具原始输出、系统提示词、图片文件或来源Agent的资源授权一起继承。图片与文件继续使用当前会话附件或已有分支复制流程。
- 引用是明确选择时的消息快照标识，不自动把来源后续新消息加入。用户点击更新才重新取完成消息；没有可引用正文或超限时明确拒绝，不静默截断半条消息。
- 只读引用受当前账号chat.read及本人归属约束，设置/移除还需当前会话管理权限。管理员不以管理身份引用其他账号的私有会话；不能引用当前会话自身。
- 新运行持久记录引用的来源/消息ID及版本，不复制正文或重算历史费用。模型调用前重新核对来源和当前绑定，来源删除、账号撤权或移除引用后停止后续调用；已发出的请求和已产生的回答不声称能够撤销。
- 外部正文作为不可信资料，并带来源标识。仅在模型请求中临时加入，不重放历史工具，不把正文作为系统指令；不把引用正文写回当前检查点或持久摘要。引用只读来源消息，不递归展开来源会话自己的引用，避免循环和隐式扩权。
- 预计Token和上下文诊断包含引用正文的输入占用，并标明估算；实际消耗仍由供应商usage入当前根账本。未知用量不补零，不复制来源账本。

## 数据与接入

新表保存当前会话的引用版本与来源/消息ID，使用外键处理会话删除，不给旧会话增加改写原记录的列。写入与运行入队在当前会话锁下固定快照；后台每次调用重新查当前绑定和消息归属。批量来源交叉引用不递归读取，也不通过锁顺序制造互相等待。

中文入口沿用ChatGPT式附件/工具区域的渐进显示：选择来源、查看当前来源和移除，不向用户展示密钥或运行实现参数。已有会话、分支和附件入口兼容。先核对本地LangChain包装模型请求和摘要中间件的顺序，确保临时正文不会进入检查点；若不能证明这一点，不开放入口。
