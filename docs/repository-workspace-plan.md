## 设计取舍与参考

参考[OpenHands仓库开发任务](https://github.com/OpenHands/OpenHands)的仓库绑定、任务工作区、差异与交付流程；沿用现有Deep Agents执行循环，不增加另一套Agent。远端提交对象与分支使用[GitHub Git Trees](https://docs.github.com/en/rest/git/trees)、[Git References](https://docs.github.com/en/rest/git/refs)等官方接口，差异语义参考[Git diff](https://git-scm.com/docs/git-diff)。

采用固定SHA的受限检出，而不是把访问令牌交给环境中的Git：服务端在本人授权下读取GitHub提交/目录/文件，校验Git对象摘要后传入任务环境；在环境中初始化任务本地Git分支。初始本地提交记录来源SHA，但不伪称下载了完整上游提交历史。普通git status/diff/本地提交可在已审批命令中使用；远端写入通过服务端受控接口，不向模型、环境变量、Git配置或成果传入连接令牌。

第一类真实服务支持GitHub；大型仓库可选择代码子目录。文件/目录/字节上限与现有32GB本地资源及工作区导出约束对应，超限明确拒绝，不静默丢文件。Git子模块、LFS下载和符号链接不自动展开。

## 用户流程

1. 中文仓库管理：本人新增GitHub仓库、基准分支/提交、可选子目录及加密令牌，检查只读连接；编辑留空保留令牌，清除需明确选择。管理员也不能读取其他人的私有连接。
2. 任务选择仓库并创建运行。发起时固定来源SHA/配置版本；后台检出到任务专属目录，显示源码位置、分支、基准SHA及检出状态。模型只获得代码和公开仓库标识。固定流程任务可复用同一工作区，权限与节点审批不绕过。
3. 编码、测试沿用现有命令审批、任务预算、文件/工具边界。提供仓库状态/差异与测试凭据；源码变更与交付文件可预览/下载，依赖和构建产物不当作源码变更自动上送。交付文件放在明确的成果目录。
4. 人工审阅准备好的文件列表、文本差异、基准SHA、测试证据及操作摘要。用户显式批准后，才创建任务远端分支/提交；不能直接改默认分支、强制推送或自动合并。
5. PR是独立批准动作，固定目标分支、标题/正文与已推送提交。关联Issue、PR及CI/检查状态作为带来源的任务证据；不将外部正文视为系统授权。

## 状态与权限

- 新增本人仓库资源、任务/运行绑定、来源文件清单、Git状态快照及外部操作记录。配置、执行、远端发布分别授权；新权限不盲目写入用户已经定制的角色，管理员可分配。
- 开始、恢复、模型/工具及远端动作前核对本人归属、账号权限、仓库启停、版本和执行租约。来源或配置变更不得悄悄换代码/凭证；仓库私有数据不因平台管理员身份跨号读取。
- 任务分支由运行ID生成，远端目标与仓库固定，不接受模型临时换URL/分支/令牌。推送只发布用户确认的变化快照；审阅后文件变化、来源分支前移或审批过期时拒绝，重新审阅。
- 外部动作在发送前标为已开始；断网/超时、进程或租约丢失后保留未知，不盲目重试。核查通过只读查询远端分支/提交/PR状态，不自动再发POST/PATCH。

## 工作区与恢复

- 所有Git命令与测试在任务环境执行，服务端只做受控HTTP、对象摘要、文件元数据和文本比较，不在宿主执行仓库代码。临时Git验证仓库不放在当前源码仓库内部。
- 初始Git操作禁用全局/系统配置、模板/钩子、外部过滤器与自动递归下载，凭证仅在服务端请求头使用。只读状态不执行仓库定义的外部diff/textconv/钩子。
- 仓库任务的工作区扫描排除内部.git与可重建的忽略项；源码/额外成果按受控清单扫描，不能靠模型改.gitignore隐藏已经跟踪的变更。内部Git对象状态以有上限的bundle独立保存，保持本地提交/分支；包含未提交变更/删除/文件模式的差量快照，不能在审批恢复时重新加回已删除文件。
- 保存前停止本任务的残余用户进程，避免后台写入造成文件与Git状态不一致；不影响其他容器或受保护的服务进程。恢复先还原Git状态，再应用差量及额外成果，校验大小/摘要/路径。不同仓库或不兼容基准不能自动套用旧快照。
- Git状态文件与元数据纳入备份、配额和隔离恢复；失败/不确定的创建或导出仍保留环境及配额，不冒充保存成功。

- 权限/跨号/撤权、令牌编辑保留/清除/不回显、路径越界/链接/子模块/大文件、资源前移冲突、审批篡改/过期、未知推送/PR不重试等在隔离数据库验收。
- 实际任务环境验证检出、编辑、审批测试、状态/差异、背景进程停止与bundle/差量恢复；凭证不出现在模型请求、命令参数、配置/成果及公开日志。
