# 整套系统部署与交接

2026-11-02，运维交付；适用于当前Windows本机工作区与 `onwer_agent`，不是公网多机发布工具。保留用户数据、密钥及未知结果任务，不提交推送。原 `start-platform.ps1` 用于首次开发准备，会启动开发版Web，不能当作生产部署验收。

## 入口与前置配置

开发和测试使用 `scripts/deploy-platform.ps1` 编排整套部署；`scripts/check-platform.ps1` 只读核对API/Web/OpenSandbox、两个执行镜像、API/Ask/Work/Ops真实心跳及受管进程。Web仍复用已验证的 `deploy-knowledge-ui.ps1`：校验PID/端口/路径、备份旧.next、生产构建、隐藏启动和失败时前端构建恢复。

先准备Docker Desktop Linux容器、Node、uv、Git、PowerShell7。基础设施配置使用 `infra/compose/.env` 和 `services/api/.env`，两个数据库密码应一致；基础设施环境文件必须由本机管理员已有配置提供，脚本不覆盖文件或打印内容。完整系统要求 `WORK_ENABLED=true`、`ASK_WORKER_ENABLED=true`；模型/API密钥仍在中文管理页面配置，不放进这些配置文件。无模型可完成部署健康检查，但真实模型运行仍待接入。

首次安装依赖、且平台API/Web及全部后台均未运行时：

```powershell
Set-Location D:\project\my_agent\deepagents
.\scripts\deploy-platform.ps1 -InstallDependencies
```

已有锁定依赖的常规发布：

```powershell
.\scripts\deploy-platform.ps1
.\scripts\check-platform.ps1
```

`-Preflight` 只检查工具、配置文件、依赖与完整系统开关，不安装依赖、不启停容器、不写数据库。它不等于运行健康验收。需要更新依赖时先单独进入维护窗口，保留备份并停止服务后执行锁定依赖安装；本脚本拒绝API/Web监听或本项目任意后台仍存活时用InstallDependencies改写环境。

## 发布顺序

1. 前置与分支检查；可选按现有uv/pnpm锁文件安装，不自行更新版本。确认Work/Ask独立后台开关已开启。
2. 仅启动既有compose项目PostgreSQL，保留命名卷；55432被无法确认归属的服务占用则失败。OpenSandbox已运行时使用本机现有密钥认证，不覆盖密钥；未运行时使用原启动脚本。缺少Coding/Browser镜像时使用原镜像构建脚本。
3. 独立短生命周期进程先取得现有准入栅栏GATE的会话独占锁，再检查正在执行的任务、工作流、资源操作、检索实验、通知发送、仓库操作、浏览器控制与备份维护；有活动操作则拒绝部署，不停止后台。锁阻止HTTP写入及Ask/Work/Ops领取新任务，父脚本收到就绪握手后才通过原受管停止脚本停API/Ask/Work/Ops；后台全部停止并确认锁仍存活后释放锁。不删除待执行、等待审批或检查点。旧库缺少准入表时拒绝在线接管，需人工安排离线维护。
4. 已有schema时等待真实服务心跳过期（最多50秒），运行原离线备份命令，并校验manifest内文件摘要；任何失败停止后续迁移。初次空数据库无旧数据备份，明确记录；已有不明schema不自动接管。
5. 迁移命令单独检查退出码，日志保存在.local；迁移失败不自动降级schema、不恢复生产数据库、不启动新后台。已有迁移可能部分应用，必须根据日志和备份核对。
6. 管理员仅通过原bootstrap命令首次创建，已存在不会重置密码。按序启动API并等待ready，再启动Ask/Work/Ops，发布生产Web，最后读取完整健康报告。

发布会有本机维护窗口，旧Web在后台停止期间不能完成请求；本工具不声称零停机。准入锁不修改维护状态表；父脚本关闭管道或退出时，helper关闭数据库连接释放锁，不遗留维护标记。锁连接失效、已有维护或停服失败均停止发布，不迁移数据库；未知操作保留核查，不自动重放。请勿同时从其他终端启动服务或绕过平台直接写数据库。

## 失败与回滚

脚本每个外部阶段检查退出码，失败记录阶段、迁移前备份位置与日志路径，不打印凭证。安全停止之后、发布完成之前失败时不自动猜测恢复后端；先检查部署报告确认哪些服务已启动，再按原受管脚本恢复经确认版本。绝不自动覆盖现有生产数据库。

前端构建失败由已有Web脚本恢复旧.next，仅对前端产物有效，不能把该行为当作全系统回滚。API源码、依赖及schema的回退需要相应已验证版本；工作区未提交改动不能靠git reset恢复。数据库备份 `app.backup verify/restore --backup <已核对目录>` 是隔离恢复验证，不是生产覆盖；生产切换须另行明确方案。备份中含主密钥，禁止上传或打印文件内容。

运行结果与当前心跳必须实际验证，不能将脚本“已启动”消息当作后台健康。检查报告不创建任务、不调用模型、不测试外部服务质量。真实浏览器/执行环境、备份隔离恢复由测试用例另验。
