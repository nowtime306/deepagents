# F06 并行汇合评测增量

日期：2026-11-04。依据 AE-03/AE-11 与 A20 的 F06，不增加任务数量。当前为开发方案；模块存在、工程测试通过都不代表正式业务验收或 READY。

## 产品需求与验收

通过正式接口分别创建、测试并发布 lower、upper 两个只读子流程，再发布固定顺序 `[lower_v1, upper_v1, lower_v1]` 的父流程。主输入 Mixed，输出须按声明顺序为 `["mixed","MIXED","mixed"]`。两个 lower 是不同的分支调用，不是额外子根或独立任务。

报告保留两个子流程初始化、父流程初始化和一次正式发布运行，共四个真实根。原始节点事件必须证实每条分支的开始、输入、转换、完成，以及全部分支完成后才汇合；不要求不同分支之间串行完成。最终数组正确而缺任一分支轨迹仍不通过。

父流程共享节点预算12，恰好覆盖三个父节点和九个嵌套节点。另以真实平台工程反例验证根预算不足时不能被每分支预算重置绕过；该工程反例单独计量和留证，不冒充第五个业务任务。目标受控工厂强制 F06 零模型/零Token，正式用量、provider 和沙箱计数均须观察为已知0，缺失不能补0。

## 开发范围

新增封闭的 F06 证据处理器，复用正式 fixture 创建、不可变发布版、原始事件、已知用量、owner 作用域观察、脱敏快照、逐CLI审计与最后收据。仅固定虚构文本、ID、版本、计数和摘要进入报告，不采集任意工具内容。

初始化快照必须封存后才允许主运行；每次写操作先登记意图，确认响应后不重复提交，未知结果停止。保存失败先毒化本次证据，禁止借重试继续业务或清理。完整在线和离线重算使用同一断言；已知业务失败可保留 FAIL，但只有全部根终态、无未决操作且资源稳定后才允许回收。

共享接线仅涉及 fixed_run 的 F06 分派、目标工厂零调用上限、固定只读观察器允许集合和能力摘要。原 A02/W01/F02/F04/A01/W03/W04 的规则、旧报告和定义不改。先开发独立模块，再审查最小共享差异，不一次性放行所有 Workflow。

## 测试与交付顺序

1. 作者验证：完整事件接受不同分支合法交错；缺分支、错误输入输出、提前汇合、重复/错序事件、伪造版本、非零/未知用量、额外副作用、篡改快照及保存失败均阻断或判 FAIL。
2. 非作者代码审查；问题修复并复审关闭后，独立工程测试。真实 API 根预算不足反例使用全新隔离库，不执行模型或沙箱。
3. 生成固定提交及能力摘要，运维用新环境只执行 F06 一次；封存四根原事实、审计、报告和精确回收收据，再由测试角色只读独立复算。
4. 验收后记录分支/提交/范围，不增加生产迁移、服务或付费调用。不引入新中间件、SSE 页面或浏览器绕行。正式平台页面和 B/C/D 按原阶段门禁继续。
