# 浏览器工作台实施设计

2026-11-01，阶段六后续。当前基线为后端287 / Chrome28通过、57迁移；工作流与分支首批已交付。现有浏览器每组操作都重新打开，因此无法连续交互或保留登录。本文件先保存设计，再编码验证；旧入口在新路径通过验收前保持原行为。

## 行为与权限

1. 同一浏览器任务的操作组共享实际浏览器进程、页面和标签；第一组需要打开页面，后续可继续读取、填写和截图。模型发起的操作仍逐组审批、写操作收据；发生未知结果时不能自动重放。
2. 实时视图由登录用户通过本人任务入口读取截图和标签状态；不公开远程调试端口或管理密钥。任务运行中仅可观看。用户先安全暂停，再开启短期人工控制；释放控制并确认状态已保存后才允许智能体恢复。普通结束控制保留暂停页面，显式关闭环境才销毁浏览器。
3. 审批暂停保留本任务的实际浏览器，人工接管使用同一页面；浏览器尚未由任务打开时，不额外分配一个空环境。保留期间继续占用浏览器配额，用户可结束或释放；环境过期后由用户显式恢复任务，从最近登录和页面地址重建，再接管。JavaScript运行栈不跨进程恢复，界面明确说明页面重新加载，不重放暂停前动作。
4. 登录状态只在同一本人任务内复用，不在不同任务或账号之间共享。Cookie、localStorage、IndexedDB及会话存储按授权域名过滤后保存，整体有大小限制；无法导出的状态明确提示。硬件认证和网站主动使登录失效仍需要用户重新登录。

## 运行与凭证边界

- 在任务的浏览器环境内使用单一受控进程，运行于专用UID1001；模型命令继续UID1000。私有浏览器目录权限0700，模型不能读Cookie文件或进程内存。可信启动与必要文件读取通过管理接口完成，不向模型开放提权命令。
- 浏览器进程生成随机通信令牌，令牌和状态用现有主密钥加密存入数据库。状态、令牌和人工输入不放入命令行参数、模型上下文、工作区成果、审批参数或公开日志。
- 浏览器服务仅通过现有OpenSandbox代理在服务端访问。先用随机挑战与HMAC验证服务身份，再发送私有请求，避免任务内其他进程抢占端口冒充浏览器；模型侧不知道通信令牌。
- 浏览器请求继续受任务域名、HTTPS及底层私网拒绝策略约束，关闭未授权跳转、弹窗目标、WebSocket与Service Worker。人工操作也不能越出任务授权域名。
- 人工操作使用本人权限、短租约和请求标识，重复请求不再操作页面；只保存操作种类与安全摘要，输入内容不持久入账。未知结果停止并要求检查，不自动重试。
- 暂停/结束前导出有界登录状态并加密保存；暂停的实际浏览器按原任务归属保留，恢复时换用新执行租约并重查权限，人工控制有效期间不可认领。任务工作区成果仍沿用现有校验与回收机制。控制创建/销毁的未知结果占用原资源配额，后台按安装命名空间核对，不把未确认销毁当成空闲。

## 开发与验收

1. 浏览器常驻进程、带认证的固定操作协议、私有状态与连续操作 → 实际容器两组操作保持同页/标签；UID1000无法读取私有状态；错误令牌/伪服务/超大请求均拒绝。
2. Work接入、加密状态、预算/审批/取消和回收 → 隔离数据库及本机接口替身证明重启恢复、来源撤权、域名过滤、未知请求不重放，备份可解密新增状态。
3. 本人实时视图与暂停后人工控制 → 两个并发控制请求只有一个成功；过期/跨用户/运行中操作拒绝；释放前不得恢复模型；实际Chrome验证点击、输入、滚动、重新登录与窄屏。
4. 生产构建与完整回归、备份恢复、迁移和重启 → 原数据/密钥摘要不变，测试样本仅按明确记录清理。真实网站账号由用户接入后再验证；先用容器内的受控测试站点，不发真实外部模型或业务请求。

## 依据与限制

核对本地已安装OpenSandbox SDK的 `Sandbox.get_endpoint` / `connect` 和 `SandboxEndpoint`，使用现有server proxy；参见[官方代理端点测试](https://github.com/opensandbox-group/OpenSandbox/blob/main/server/tests/test_routes_endpoint_behavior.py)。登录态复用依据[Playwright认证](https://playwright.dev/python/docs/auth)与[BrowserContext API](https://playwright.dev/python/docs/api/class-browsercontext)，会话存储另行处理。保留现有Playwright1.56镜像依赖，不直接套用更新版本才提供的接口。
