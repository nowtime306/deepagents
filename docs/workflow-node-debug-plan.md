# 工作流逐节点调试

2026-11-02，基于已有工作流画布、单节点临时图、运行事件和持久任务审批实施，不迁移用户数据，不提交推送。

参考 [n8n 官方部分执行说明](https://docs.n8n.io/build/understand-workflows/understand-executions/types-of-executions.md)的节点执行与输入复用交互，以及 [Dify 单节点运行实现](https://github.com/langgenius/dify/blob/main/api/core/app/apps/workflow_app_runner.py)的独立图和测试变量。这里明确只执行所选节点；复合节点会执行其配置的子流程，不自动运行原图上游或下游。

1. 每张节点卡片、选中节点工具栏、右侧配置面板均提供明确的测试入口。测试区展示节点名称、输入来源和可编辑测试值，支持复用同修订运行的真实输入。
2. 测试区直接展示运行状态、实际输入/输出、耗时、分支与错误，保留运行历史和画布节点状态。重复测试使用新的运行编号，网络未知结果不自动重发。
3. 全部15类节点均提供单独测试。只读节点沿用独立临时图；MCP的其他变量引用由测试值显式提供。代码和人工审批节点创建独立持久任务并沿用原审批/执行环境，不执行原图其他节点。
4. 单节点运行保留原画布快照，不设置整流程已测试标记；后台同步也不得因单节点成功而解锁发布。权限、资源归属、修订校验与重复编号保护继续生效。
5. 验证：隔离数据库覆盖输入、范围、权限、重复提交及发布边界；本机执行环境验证代码/审批独立执行；Chrome验证所有节点入口、输入复用、运行中/成功/失败、重测和390px页面。真实外部模型继续跳过。

## 实施与验收

已实施并部署。所有15类节点卡片直接提供“测试”按钮，选中节点工具栏和右侧配置也有文字入口。当前草稿同修订的单节点测试完成后，可直接连续重测，不必先返回编辑；历史快照与发布版本仍保持只读边界。

测试区显示节点名称、输入来源、可编辑主输入和MCP其他引用变量；可复用当前修订最近运行的实际输入。单节点运行保存测试变量，复用MCP测试时不会丢失其他变量。结果直接显示实际输入/输出、耗时、条件命中/默认、错误及节点轨迹，审批类显示任务入口与真实等待状态。

代码与人工审批节点使用原任务后台、执行环境和审批检查点。测试图只保留所选节点与必要的临时起止节点，不运行原图其他节点；代码/审批在审批前等待，通过后继续。每次运行有独立编号，重复编号返回冲突且不创建第二个任务。后台完成同步明确排除单节点运行，不解锁整图发布。
