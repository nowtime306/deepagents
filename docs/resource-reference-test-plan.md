# RDC 资源引用解耦测试计划

日期：2026-11-03。依据：`resource-reference-decoupling-requirements.md` v1.0。状态：待执行计划，不是验收结果。

本轮只编写计划和体验建议，没有执行独立 QA。此前作者自测、类型检查、构建结果、独立代码审查分别保留原属性，不能折算为本计划通过。进入验收前，须先完成已发现问题的修复和独立复审；修复状态以根任务确认的冻结提交为准。

## 1. 开始条件、环境和记录

1. 根任务提供冻结提交 SHA、文件清单/摘要、迁移清单和独立复审结论。不得边修改同一范围边宣布该范围验收通过。
2. 使用随机独立数据库 `owner_agent_rdc_qa_<随机>_test` 和独立数据目录、CredentialVault、Qdrant目录。创建/回收前校验名称前缀与 `_test` 后缀；测试连接不得指向生产业务库。进程显式设置测试配置，不加载生产工作进程或发送队列。
3. 从空库执行全部迁移；另建一份仅含升级前结构的独立测试库，写入测试用旧数据后升级。先备份测试库和测试私有目录，记录恢复步骤。禁止使用真实用户资料或复制生产密钥作为测试输入。
4. 创建 A、B 两个账号，资源各自私有。A 可在测试中切换管理员、具有单项 read 权限的角色和无权限角色；不把“另一个账号”误当作“同账号只读角色”。管理员也不得绕过私有资源 owner 范围。
5. 所有模型、向量、重排、MCP、仓库、通知服务均使用受控替身。替身只接受测试数据，记录调用次数、目标、资源 ID、请求参数和收到的测试凭据标记；输出证据时去掉凭据内容。
6. 为队列/首次调用/第二次调用/响应返回分别设置可释放的屏障，不用固定 sleep 猜时序。替身支持已知成功、发送前拒绝、发送后断连、超时、未知结果、输出维度改变、相同维度不同向量身份等模式。
7. 测试用秘密标记涵盖 API key、token、签名密钥、URL userinfo/path/query、请求头、命令自由值。只在隔离输入中使用；证据搜索历史、公开快照、错误、日志、导出响应是否含这些原文，报告匹配位置而非再输出秘密。
8. 每条用例记录：用例 ID、冻结 SHA、时间/时区、测试数据 ID、前后状态、实际目标与调用计数、HTTP/事件结果、快照与历史关联、证据路径、通过/失败/阻塞/未执行。不能用测试总数替代 RDC 覆盖。

### 三类验证分开

- **API/数据验收**：真实隔离 PostgreSQL、真实应用 HTTP 路由和事务，外部模型/连接用替身。可证明授权、CAS、快照、时序、状态与幂等；不能证明真实供应商效果。
- **实际页面验收**：只在此前浏览器访问拒绝得到明确解除、且测试环境页面获准后执行。当前 3100/3131 页面访问曾被拒，继续禁止访问；不能换浏览器、端口、工具或远程浏览绕过。源码、构建、测试发现检查均不等于页面验收。
- **真实外部联调**：另行获得此前暂缓联调范围的授权后才执行。真实模型、外部 MCP、远端仓库写入、外部通知仍未纳入本次替身验收通过。

## 2. 受控样例与执行入口

准备聊天模型 A/B、文本向量 E1/E2、重排 R1/R2、多模态向量 M1/M2；E1/E2 即使都输出二维也要有不同实际身份。向量替身能对同一模型返回二维或三维，兼容迁移样例由管理员明确核对后登记证据，不自动把相同维度当兼容。

准备智能体发布 v1、具有固定成员版本的团队、工作流 v1/v2及固定子流程版本、启用的 Skill/MCP、文本知识库、长期记忆、图片/视频索引、仓库连接和通知通道。

现有测试源码可作为编写/执行脚本的起点，但需要核对冻结实现和断言。重点包括 `test_rdc_configuration_history.py`、`test_rdc_history_http.py`、`test_model_routing.py`、`test_automation_notifications.py`、`test_memory_vectors.py`、`test_knowledge_usage.py`、`test_quality_gate_api.py`、`test_multimodal.py` 与新增运行恢复测试。以下用例的缺项须补测试或人工受控步骤，不能仅运行这些文件后自动判为全覆盖。

可用 HTTP 观察入口：

- 配置历史：`GET /api/v1/resource-configurations/{kind}/{id}/changes`、`GET /api/v1/configuration-changes/{audit_id}`。
- 运行配置：`GET /api/v1/resource-runs/{mode}/{id}/configurations`；mode 为 ask/work/workflow/resource，分别核对原业务查看权限。
- Work配置恢复：`GET/POST /api/v1/resource-runs/work/{id}/configuration-recovery`，确认请求须使用本次预览的阶段与摘要。
- 工作流历史切换：`POST /api/v1/workflows/{id}/versions/{version}/set-current`，提交最新 release_revision。
- 通知：`GET /api/v1/notifications/deliveries`；`POST /api/v1/notifications/deliveries/{id}/retry`，包含明确的重复风险确认与 expected_target。

## 3. RDC-01 智能体与自动任务

**01-A 原问题回归**：发布自动任务助手 v1并记录模型 A修订1；只将 A温度/地址/密钥分别保存为新修订；使用原 v1创建普通对话、一次定时任务和批量任务，再让队列开始执行。断言业务版本仍是 v1、创建成功后确有任务记录，实际调用采用开始时的新配置，无 AGENT_MODEL_CHANGED 或要求重新发布。证据：HTTP创建响应、队列记录、替身请求、运行配置。

**01-B 实际不可用仍拒绝**：分别删除、停用 A，或改成向量用途/不支持的协议；重试创建与已入队执行。断言明确指出模型不可用/用途不兼容，外部调用为0，不把草稿/解析失败说成任务已创建。

**01-C 能力未知**：v1需要图片、工具或原生联网，分别将对应能力设为未知/不支持。断言未知不会被当支持；错误定位资源并提供核对入口，保留能力明确支持的正例。

## 4. RDC-02 团队成员

**02-A 不级联发布**：父智能体固定成员版本 C-v1，成员模型修订更新；保持父子业务定义与版本不变运行团队。断言父子无需重发，成员实际使用当前可兼容模型，调用台账能区分主助手和成员。

**02-B 固定业务版本**：成员发布 C-v2但父团队仍绑定 C-v1；运行可识别指令替身。断言仍执行 C-v1指令，不因为“最新”而切到 C-v2。

**02-C 撤销即时生效**：在成员调用前及两次成员调用之间，分别移除团队授权、下线 C-v1、停用成员模型、撤销成员所需工具/知识权限。断言后续受限调用被拦截；不得将普通模型维护误报为成员授权撤销。

## 5. RDC-03 工作流与历史回退

**03-A 直接切回旧发布版**：创建并测试/发布流程 v1/v2，更新外部模型地址/凭据；用最新 release_revision将 v1设为当前，执行当前入口。断言无需复制同逻辑草稿重发；实际节点、连线、参数、Schema、预算来自 v1，模型使用当前兼容配置。

**03-B 业务版本不漂移**：同时运行明确绑定 v2的调用、已开始的 v2运行、固定子流程版本的嵌套运行；切当前指针到 v1。断言三者均保留原明确版本/本次配置，新的当前版本调用使用 v1。

**03-C 入口矩阵**：对只读执行、Work持久流程、外部 API、Ask工具、Work工具、嵌套子流程分别重复普通配置更新场景。断言语义一致；缺失资源、节点输入/工具结构不兼容时定位节点与资源，不一律要求重发流程。

**03-D 保留草稿门槛**：更改流程业务节点后不测试直接发布，应按原整体测试门槛拒绝；执行测试再发布应通过。另用过期 draft/release revision写入，确认 CAS仍有效。

## 6. RDC-04 运行时序与恢复

**04-A 排队后更新**：暂停消费者，入队运行，更新模型/路由，再释放消费者。断言首次实际执行选择最新可用配置，入队预选不应提前决定实际配置。

**04-B 调用中更新**：同一运行调用模型两次；第一调用完成后更新名称、参数、密钥、地址再释放第二调用。断言仍采用该运行首次确定的配置/凭据，新运行采用更新后的配置；不得靠把旧 revision覆写成当前值通过台账检查。

**04-C 检索设置也固定**：同一运行检索两次，在中间修改关键词阈值、重排绑定、记忆检索绑定。断言旧阶段设置和结果语义不漂移，记录可解释阈值及模型；新运行采用新值。此项专门复核独立审查发现的问题。

**04-D 暂停/同进程恢复**：在已完成一次受控写操作后暂停，普通配置更新后恢复。断言复用本阶段配置，已完成写操作调用计数仍为1。

**04-E 重启/凭据恢复**：停止测试进程并清空进程内凭据缓存；仅同目标轮换凭据后恢复，应使用当前凭据并标明凭据更新。若服务目标/协议需要切换，应进入待确认恢复，预览差异、确认摘要及新阶段；预览后再次改配置，旧摘要不得通过。

**04-F 取消与未知结果**：执行期间取消、停用模型、撤销权限或使租约失效，确认后续调用停止。写操作发送后断连制造 UNKNOWN，恢复不得自动重做该写入；沿用核对流程。

## 7. RDC-05 配置历史

**05-A 字段/分类矩阵**：分别修改温度、显示名、地址、密钥、默认标记、用途、启停以及 MCP/路由/检索/仓库/通知配置。核对每条资源 ID、当时名称、操作、前后修订、服务端操作者、时间、差异、分类及关联 ID；自由字段只展示用途脱敏结果。

**05-B 原子性**：两个编辑者携带相同 revision并发保存，只有一方成功；在配置写入后制造事务异常。断言失败/回滚不出现成功历史，成功方配置与历史一致且不被覆盖。

**05-C 隐式联动与可信actor**：设置新默认模型，核对新旧默认双方均有历史且同 change_id；两次独立 HTTP请求须有不同关联 ID。发送伪造 X-Actor/X-Change-ID和额外 actor字段，不得冒充其他操作者。

**05-D 删除与旧基线**：删除无运行引用的资源后，原 owner仍能查历史；对旧数据升级仅出现明确 BASELINE，不生成过去发生过的虚假修改。基线时间必须是上线/迁移时间。

**05-E 权限与秘密**：A/B互查私有历史、管理员查另一 owner私有历史、无 read角色查本人历史均须拒绝；模型/MCP/路由历史仅管理员。检查测试秘密不进入差异、错误、日志和导出；key只显示设置/更换/清除及无密钥修订标识。

## 8. RDC-06 运行追溯

**06-A 多资源实际配置**：主助手、两个成员、多模型、Skill、MCP、嵌套流程分别使用可识别替身；核对业务版本、资源 ID/修订、解析时间、使用时间、阶段、模型/协议/服务目标、有效参数、内容摘要及调用关联。已解析但未调用的资源不得标为实际调用。

**06-B 失败与历史缺失**：分别在资源解析前、解析后未调用、调用中失败；运行详情不得虚构调用。升级前运行无快照时明确“历史未记录”，不能用当前配置充当当时配置。

**06-C 对比与链接**：运行完成后更新资源；运行配置仍显示原值，对比显示当前差异，打开修改记录后能回到原运行且保留选择状态。恢复后多阶段分别显示，不覆盖旧阶段。

**06-D 一致读取**：在模型主体/能力声明读取之间设置屏障并提交一次配置保存。返回必须是完整旧配置或完整新配置，不能出现“旧 revision/旧端点+新能力”的混合快照。

**06-E 权限**：对四种mode分别验证本人有权限、本人权限撤销、其他 owner和不存在运行。任何响应都不得包含执行配置密文、API key或自由URL秘密。

## 9. RDC-07 模型路由

**07-A 普通维护**：确认接收方后改名称、密钥、健康阈值、冷却时间及候选排序；旧智能体无需重发，既有授权不因无关修订失效；新运行按最新策略选择并记录原因。

**07-B 接收范围变化**：新增候选、修改目标、扩大图片/工具/联网数据范围，未确认前发送次数为0。名称/密钥更新不冒充新接收方；确认后仅向已同意候选发送。

**07-C 固定与撤销**：运行已选A后改变候选顺序/普通配置，不重选B；A停用或路由授权被撤销时仍拒绝后续调用。请求已发出结果未知不得自动向备用模型重发。

## 10. RDC-08 向量兼容

**08-A 四入口维护**：文本、长期记忆、图片、视频索引分别建立可识别向量；更新key/名称/default后复用，不能因通用revision要求重建。

**08-B 身份与维度反例**：同维不同模型、相同模型输出不同维度、预处理改变分别验证不混查旧向量；给出具体核对项或重建提示。长期记忆不得出现“全部向量跳过但hybrid且无告警”的假正常结果。

**08-C 地址迁移**：只有地址变化且管理员明确核对同模型版本/输出/预处理并登记兼容证据时才复用；无证据先提示未知。恶意用相同维度声明不同模型不得自动通过。

**08-D 重排独立**：仅切换重排模型，不重建原文本向量；记录排序行为变化。向量无法用时已有关键词降级仍可用并明确影响，旧向量资料保留。

## 11. RDC-09 评测与质量门禁

**09-A 历史保持**：执行受控题集实验，保存文档/参数/模型/结果；更新配置后旧结果不删除不改写。仅密钥/显示名维护时仍适用；真实模型/文档/检索行为变化时给出适用性与重测建议。

**09-B 门禁分离**：同一过期效果证据，严格门禁关闭时不得仅因通用revision阻止发布；开启时按当前效果配置要求有效证据，保留题目数、引用/拒答标注和原有门槛。

**09-C 进行中实验**：题目间维护key应保持固定条件；改变文档或检索行为且无法固定时实验明确中断并标受影响部分，不把混合配置计为SUCCEEDED。

**09-D 真实与合成区别**：合成回归题不能冒充真实质量证据；外部模型缺少有效用量或结果未知时不算完整成功，不自动重复计费调用。

## 12. RDC-10 MCP、Skill与审批

**10-A 当前资源/固定正文**：旧智能体版本引用同Skill/MCP ID；更新正文或工具定义后，新运行取当前可用内容并记录摘要，旧运行沿首次确定内容，无需重发智能体。

**10-B 保留兼容检查**：删除/停用工具、禁用工具项、变更参数Schema、把只读改为写入或撤销执行环境能力，必须拦截并定位工具，不把未知能力当支持。

**10-C 审批精确绑定**：写工具/Skill脚本在批准后分别只轮换密钥、改显示名，应可按同目标继续；修改目标、脚本/命令内容、关键参数/范围后旧批准必须失效并要求重新确认。替身计数证明未执行修改后的未批操作。

## 13. RDC-11 仓库

**11-A 同身份维护**：固定仓库slug、ref、基础commit、源码范围、任务分支和成果摘要；只改显示名或凭据后恢复/读取证据，仍使用原源码与成果，同身份当前凭据可用。

**11-B 身份/来源变化**：改变slug、目标分支、subdirectory或源码基础后尝试恢复/发布，必须展示差异并拒绝静默套用旧成果；旧推送批准不能用于新目标。

**11-C 幂等与未知**：受控push/PR发送后断连，核对流程不会自动重发；恢复不能重复已完成操作。全部使用替身，不实际推送远端仓库。

## 14. RDC-12 通知

**12-A 冻结消息**：创建待投递记录，之后改通知表文本/通道名称并轮换签名key。投递使用原冻结消息与原目标、同目标当前凭据；替身验证正文及目标，历史中无签名key。

**12-B 目标变化暂停**：创建旧目标A消息后改到B，派发应PAUSED且发送次数0；新消息使用B。查看旧/当前安全摘要，未明确确认不能改投。

**12-C 确认竞态**：界面/API看到B后后台再改为C；以 expected_target=B确认重发须409且无新投递。刷新确认C后才建新记录，retry_of指向原记录，旧记录和冻结正文不被改写。

**12-D UNKNOWN与权限**：制造发送后断连，定时派发不自动重发；显式确认重复风险后才能建重发记录。通道停用、通知权限撤销仍拦截；旧记录缺目标/正文证据不能用当前值补造后自动发出。

## 15. RDC-13 一致性与权限回归

**13-A 保留保护矩阵**：覆盖多人CAS、账号停用/角色撤权、版本下线、资源停用、任务取消、执行租约、预算、审批参数和目标、向量/工具/Schema兼容检查。每项都应有“普通维护不误伤”和“真实边界变化仍拒绝”的成对正反例。

**13-B 另一轮内容与身份流程**：运行中的内容快照不被后续编辑无记录替换；找回密码/OAuth一次性凭据和有效期检查保持原逻辑，不因本次解耦取消。使用本地身份流程替身，不发送真实邮件/短信。

**13-C 错误语义**：仅配置维护不得报权限撤销；真实撤销不得被归类为普通维护而放行。保存失败、开始失败和执行失败分别有明确状态，不制造成功通知。

## 16. RDC-14 实际页面验收（当前阻塞）

以下均为待执行页面用例，当前不访问页面，不记通过。

**14-A 七类资源入口**：模型设置、MCP卡片、模型路由、知识库配置、记忆检索设置、仓库卡片、通知通道可在原位置展开“修改记录”。展开才加载，刷新失败显示明确错误，切换资源不能短暂显示另一资源旧记录。

**14-B 运行排查闭环**：从失败运行展开“本次资源配置”，识别阶段、实际调用与仅解析项、业务版本及当前差异；进入对应历史后返回原运行，筛选/选中项不丢失。旧数据明确未记录。

**14-C 只读与管理员边界**：同账号仅有对应read权限时能看本人追溯，无保存/编辑/停用/重发入口；管理员专属全局历史对普通账号不可见；跨账号不暴露名称和差异。

**14-D 定位与恢复文案**：模型不可用、能力未知、向量不兼容、节点/成员错误、审批目标改变、待确认恢复均有具体原因和可行入口。普通修订变化不出现“重新发布/新建运行”提示。

**14-E 通知确认**：原/当前目标host及摘要清楚区分；取消确认不POST；确认目标时显示实际将采用的当前摘要并提交expected_target；UNKNOWN不自行重发，retry_of可回看旧记录，历史缺失时说明原因。

**14-F 窄屏/键盘/编辑保留**：1440、1024、390、320像素检查长字段、UUID、摘要和前后值不横向溢出；Tab/Enter可展开、焦点可回到原入口；打开历史不提交/清空未保存设置，取消弹窗也不触发外部调用。截图和键盘记录必须来自获准测试页面，不能以静态推测代替。

源码起点：`apps/web/tests/resource-configuration-history.spec.ts` 等。此前只做过测试发现检查，5个用例未实际浏览执行；本计划还要求补齐运行追溯及恢复交互，不因这5个用例存在而宣称已覆盖全部页面。

## 17. 升级、回退和结束门槛

- 用升级前“排队、运行中、待审批、暂停、未知结果、已有向量/旧实验”样例执行迁移。不得批量重发业务版本或伪造旧pins；旧向量证据不足明确待核对；旧投递缺证据不能改投。
- 验证测试备份能恢复。回退代码前停止新投递/执行；新增PAUSED、执行阶段、未知结果和retry关系必须保留，不能简单删除新列或把PAUSED批量设为PENDING来“恢复”。
- 结束时按RDC编号逐项标状态，另列浏览器未验收、真实供应商未联调、环境限制和仍未覆盖反例。所有P0/P1阻断修复并复审；有范围缺口不得以“后端用例全绿”宣布完整产品验收。
- 记录最终冻结SHA、迁移版本、隔离数据回收结果。独立QA完成后再由用户/根任务按原流程决定是否部署；本计划不授权部署。
