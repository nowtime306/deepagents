# 工作流可用性与数据编排需求（Dify 参考版）

2026-11-03。产品需求冻结版 v1。本轮工作区 `D:\project\my_agent\deepagents`，分支 `onwer_agent`。范围为现有工作流增强，保留全部用户数据、模型密钥与已有未提交改动。

## 1. 调研结论与设计取舍

Dify 将画布、节点配置、运行调试和发布组成一个工作台，而非仅显示连线。官方 [Workflow Studio](https://dify.ai/workflows) 强调可视化编排与节点执行证据；本平台借鉴这种任务导向的操作层次，不复制品牌或引入其运行时。[Dify 官方仓库](https://github.com/langgenius/dify) 用于核对产品定位及开源实现边界，星数会变化，本需求不使用未经固定的排行数字。

Dify 的 [Variable Inspector 官方文档](https://docs.dify.ai/en/cloud/use-dify/debug/variable-inspect) 允许查看运行数据，并以编辑后的测试值调试下游，同时保留原记录；[官方 1.5 调试说明](https://dify.ai/blog/dify-1-5-0-real-time-workflow-debugging-that-actually-works) 展示单节点复测减少整图重跑。我们选择“真实运行变量总览 + 显式填入单节点测试值”，不把本地改值写回原运行，不自动重新调用上游模型或工具。

Dify 官方[模板节点文档](https://docs.dify.ai/en/cloud/use-dify/nodes/template)提供文本组合思路。本平台本轮只实现固定占位符替换，保持现有字符串节点契约，不开放任意模板语言、脚本求值或隐式变量。

以上是参考产品行为后的本地实现决策，不宣称与 Dify 功能或协议完全兼容。示意交互见 [本地 UI Demo](demos/workflow-dify-demo.html)，演示数据不接模型、不代表已实现。

## 2. 当前真实能力与缺口

依据 `workflow_definition.py`、`workflow_compiler.py`、`workflow_runtime.py`、`workflows.tsx`、`workflow-editor.tsx`、`workflow-run-trace.tsx` 及既有专题验收：

- 已有列表创建/编辑，独立 React Flow 画布、连线、复制删除、右侧节点配置、修订号保存、历史快照、测试后发布与不可变版本。
- 已有 15 类节点：开始、结束、LLM、Agent、RAG、MCP、HTTP、条件、转换、子流程、迭代、并行、条件循环、人工审批、代码。单节点测试、真实输入输出/耗时与持久任务审批均已有，本轮保留而非重复建设。
- 已有输入输出 JSON Schema、关键词条件与有限 JSON 字段提取、资源归属/版本固定、模型预算和未知结果不自动重放。
- 主要缺口：新建只有空白/AI 问答；节点库平铺不利寻找；输入来源下拉暴露不保证执行的节点；失败以首个错误为主、难以定位；已有“复用最近输入”及 MCP 测试变量复用，但只有分散轨迹，缺少集中变量总览和明确来源/失效提示；缺少组合多份上游内容的简单模板；编辑缺少撤销重做与整理。

## 3. 本轮完整交付范围

P0 为阻止误配和保障数据路径，P1 为提升创建/编辑效率。本轮两级均实施；不是只写未来路线。

### WF-D01 / P1：场景模板库

创建弹窗保留名称/模型，增加带用途、节点数量、资源要求的模板卡片。提供五个模板：空白（保留 blank）、AI 问答（保留 llm）、JSON 字段提取、关键词分流、模板报告。知识检索与工具仍从节点库配置，不纳入即用模板。

验收：选择模板创建后直接进可编辑画布；默认资源不得硬编码某个用户的模型、知识库或 Agent ID；缺资源显示待配置。至少 JSON 提取、分流及模板报告可在不调用真实模型的本机测试中成功运行。模板卡显示的样例输入/预期输出与实际定义一致。原空白/问答入口兼容。

### WF-D02 / P1：可搜索、分组的节点库

按“AI 与知识”“数据与逻辑”“工具与人工”等任务分组，支持按中文名、用途及 kind 搜索；空结果可清除关键词。保留全部既有节点入口及限制说明，增加模板转换快捷项（复用转换 kind）。

验收：输入“知识”“条件”“template”等可定位相应项；点击添加并选中配置，结果在当前视口可见；关闭重开不产生多余节点。只读历史/发布快照不可添加。保留窄屏可用性，不把画布挤成细条。

### WF-D03 / P0：执行前校验与定位

工具栏提供“检查流程”；显示当前草稿的多条问题，包含稳定 code、节点标识（全图问题可为空）、字段及中文说明，区分结构/引用/参数等类别。点击问题选中相应节点并打开配置，节点在画布可见。完成修改后重新检查，不保留旧“通过”结论。

后端校验为只读，无模型、工具或业务写入。图引用、必经关系、资源参数格式等检查与现有执行规则保持一致；保存未完成草稿仍可用。若检查不覆盖实时资源可用性，结果必须明确“配置检查，不代表资源已就绪”，真实运行/发布仍执行现有完整权限和资源检查。不得显示一条空泛“全部就绪”放宽发布。

验收：断线、非法输入来源、缺必需参数可各自定位；多个可独立判定的问题一起返回，不将检查接口失败当作通过；无权限/跨账号不得检视他人草稿或资源；检查不新增运行/模型用量。结构严重无效时可先返回结构问题，修复后再进入依赖检查，避免伪造完整性。

### WF-D04 / P0：可靠的变量来源与 JSON 字段提取

节点主输入和 MCP/template 引用选择，仅列根流程输入及当前节点所有执行路径必经的前置节点输出。不能以“任意祖先”代替必经检查；下游、自己、未执行的互斥分支不得成为有效引用；保留名 input 不得用作节点 ID。新选择器优先推荐“流程输入”，已存在合法开始节点 ID 引用仍保留并显示“开始输出（兼容，建议流程输入）”，不破坏旧 v1 草稿/发布流程。旧有失效引用应显示错误并可修复，不默默改绑。

在转换节点 JSON 字段提取操作中明确源变量、点分路径示例与数组索引（如 `customer.name`、`items.0.title`），可用测试值查看提取结果；不新增全 Node 通用 `input_path` 协议，不承诺自动发现所有外部 JSON 字段。字段错误以节点失败展示，不把缺字段伪成空字符串成功。

验收：直线 A→B 时可选择 A；条件分支汇合后不能直接引用仅某分支有的值；删源节点后可发现失效引用。合法 JSON 文本/数组字段提取成功；非法 JSON、缺字段、越界失败可追踪，现有可处理转换错误分支保持。服务端拒绝绕过 UI 的非法引用。

### WF-D05 / P0：受限模板转换

转换操作新增“模板组合”，模板文本可含 `{{input}}` 与 `{{node_id}}`，分别表示根流程原始输入和显式引用的必经上游节点输出。普通文本、中文和重复引用均可组合。界面提供变量插入而非要求用户记 ID。

模板不支持点号路径、循环、条件求值、函数、环境变量或凭据；需要 JSON 字段时先用 JSON 字段提取节点。未知引用、未闭合/不合法占位符须明确报错，不能静默原样输出。按现有 40,000 字输出及定义大小预算约束扩展，服务端在替换前后做有界检查，错误可沿既有转换错误分支处理。

验收：输入和两个顺序上游文本可以组成最终报告；同一路径各值真实进入模型前提示或结束输出；跨分支/未来引用拒绝。无第三方模板引擎或 eval。单节点测试仅执行当前节点，通过显式 `debug_variables` 提供其他引用的测试值，缺值提示，不自动执行上游。草稿、完整执行、单节点、发布版、Work 执行对模板遵循同一语义。

### WF-D06 / P0：运行变量检查与复用

画布测试面板增加“变量”视图，与结果/轨迹并列。在现有“复用最近输入”基础上增加集中可选来源与失效保护，不把复用入口当作全新能力。按真实运行节点显示名称/ID、状态、实际输入输出、值类型（文本或可解析 JSON）、来源运行及修订。长值有可展开详情，避免每个字符都占满画布。失败、未运行、等待审批没有真实输出时明确为空/不可用，不伪造结果。

选择变量可查看或复制值；选中一个节点后，可将同草稿修订真实运行记录里的该节点输入及所需上游输出填入可编辑的单节点测试区。操作仅复制为测试值，不改原始运行记录，不污染发布配置；仍需用户明确点击测试。可按当前定义解析模板/MCP的其他引用。

验收：完整运行后能浏览各节点数据；选中历史失败事件不残留上一成功输出；切换运行清空旧变量；旧修订不能被标成当前可复用数据；修改后的测试值只影响新建的单节点运行，原运行内容及用量不改；单节点成功不解锁整图发布。对代码/人工审批仍沿原任务授权及审批执行，不做调试绕过。

### WF-D07 / P1：可撤销的画布编辑与整理

支持当前编辑会话的撤销/重做按钮与常用快捷键（Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z）。记录节点增删/复制、连线、配置和位置的业务状态；输入框内文字编辑保留原生撤销，不抢按键。提供“整理画布”，按拓扑层级和分支排布，保留节点及边语义。

验收：增删/连线/移动及参数变更能恢复并重做，产生新编辑后清空 redo；记录有上限，拖动一次形成一个步骤；保存后可继续本会话撤销但不改变数据库修订号规则。切换流程清空编辑栈，历史/发布/运行中不允许修改或整理；撤销恢复的图仍需重新检查/保存/整图测试才能发布。未完成/有环草稿整理不能挂死，提示先修正或有界布局。原手动布局保存刷新不丢。

### WF-D08 / P0：兼容、权限与状态

沿用既有同步测试 HTTP200 与运行事件查询，工作流不改成 SSE 或新异步202接口。智能对话已通过的 SSE 保留。旧定义 schema_version=1 与已发布版本无需迁移即可运行；新增参数缺省不改变旧流程行为。

读权限不能写入、运行、发布；管理流程和运行结果均后端校验归属。审批、真实外部写入和未知结果不自动重放规则维持。未配置真实模型时明确显示需配置，不能以 demo 输出冒充模型结果。

验收：旧工作流、15类单节点、修订409、不可变版本、发布测试门槛、Work审批/恢复、Ask SSE定向回归。真实外部模型/业务工具按用户要求继续跳过，使用隔离库和本机协议替身验收；报告明确本机证据与外部待接界限。

## 4. 界面流程

工作流列表 → 新建 → 场景模板卡 → 基本信息 → 创建画布。画布顶栏：返回、名称/保存状态、撤销重做、整理、检查流程、运行历史、保存、测试、发布。左上为可搜索节点库；中心保持画布；右侧按节点显示配置；检查结果可从侧栏点选定位。右侧/底部测试区包含输入、结果、变量、轨迹，画布和节点配置不被长日志遮挡。窄屏以切换面板呈现，所有按钮具有中文文本或可访问名称。

## 5. 开发与测试交接门槛

开发先据 WF-D01～08 编写开发文档和实施顺序，接口和模板语法必须与本需求一致；常规实现细节可以自行选择，超出本轮范围的功能另立需求。作者完成自验后独立代码审查，通过后 QA 才在最终冻结源码验证。测试按每个编号覆盖正常、失败、权限、旧数据及窄屏；区分单元/隔离 API/真实浏览器和真实外部服务。新 bug 返回修复并复审后复测。

部署沿用现有已审脚本，备份当前状态而非恢复旧用户库；核对实际页面构建、后台就绪、当前数据/主密钥摘要与清理归属。没有为了本轮增加必须部署的服务或依赖。

## v1.1 验收澄清：撤销与发布资格

2026-11-03，与开发及独立审查对齐，保留上文初版措辞以便追踪。WF-D07“撤销恢复的图仍需重新检查/保存/整图测试才能发布”按以下可验证规则解释：若撤销/重做后，definition、layout 及其余影响 dirty 的字段精确等于数据库当前已通过整图测试的同一修订（dirty=false 且 tested_revision=revision），可保留既有发布资格。若恢复出的状态与当前已测试修订不同，必须先保存为新修订并通过整体测试，单节点成功不替代整图测试。不因一次 undo 操作本身作废同一合法修订，也不由浏览器私自更新 tested_revision。

模板语法仍为裸 `{{input}}` / `{{node_id}}`，不扩展为字段路径或表达式；JSON 提取仍沿用 json_get。此澄清不改变只读历史/发布版本不可编辑、权限、预算和 SSE 范围。


### 同版数据值澄清：空文本与缺失变量

WF-D05/D06 沿用字符串值契约：一个上游节点的真实输出可以是空字符串；单节点测试的其他引用变量可以显式提供 `''`，不能因浏览器必填规则而将该合法值阻止提交。界面空的可见变量字段以显式空字符串提交，服务端直接请求缺少必需引用键仍为错误。既有主测试输入 min1 的接口限制保持，未扩展为任意空主输入。此处是值与缺失的区分，不放宽引用归属、路径、模板语法或输出预算。
