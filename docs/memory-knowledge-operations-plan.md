## 设计决定

自动记忆采用“用户授权来源 → 有预算的候选提取 → 人工审阅 → 生效”，不把一整段对话直接追加为系统指令。候选提取复用既有持久 Ask 后台、租约、模型修订与用量账本；使用独立的内部用途会话，关闭知识、联网、MCP、工作流和团队资源。内部会话从普通会话列表/搜索隐藏，仍归原账号，诊断和费用可追溯。请求需同时具有记忆管理、对话读取和运行权限。

- 用户选择本人会话、消息和聊天模型，明确这次会发生模型消耗；默认仅从用户表达提取可长期使用的事实/偏好，限制消息数、字符量、候选数和预算。原文作为数据引用，不授予工具权限。
- 持久提取记录保存来源消息 ID、模型/修订、根运行 ID、状态和安全错误；相同来源与配置去重。未知调用不自动重试，模型输出不合法时明确失败，不编造候选。
- 候选显示来源、标题、内容；支持编辑确认、拒绝、失效期。确认前不参与召回。相同内容不重复保存，相同范围的同名冲突需要明确选择，不静默覆盖。
- 生效记忆可限定为本人全局、本人项目或本人 Agent。召回先按账号、项目/Agent 当前授权、启用和到期过滤；工作任务没有项目上下文时不能读取项目记忆。删除来源后显示来源已删除，未确认的候选及提取副本按隐私规则清理；已确认记忆是用户独立保存的内容，仍可单独删除。
- 语义召回使用用户选定的已配置向量模型，固定索引模型修订、维度和内容摘要；配置变化后旧向量不能混用。无语义模型时明确使用关键词；不把未调用的向量分数写成零。小规模私有记忆使用持久向量缓存，不再启动一套向量服务。

知识运营补可配置分块策略、内容摘要与增量替换、逐文档解析/索引状态；旧文档与旧策略保留。扫描文档的 OCR 复用受限视觉模型路径，仅在明确选择模型与页数上限后执行，不静默安装大型模型或调用外部服务。评测集、标准证据、实验参数/结果与回答反馈持久化，区分真实数据集和合成回归，引用和无答案指标未测时保持未知。

向量调用不能静默漏记费用。增加受限资源操作记录（索引/检索）与调用类别：聊天内召回挂到原 Ask/Work 根运行，独立索引有自己的持久操作和预算。复用现有账本、价格快照及未知用量规则，文本向量输出 Token 为 0；服务商不报告输入用量则保持未知。首次使用此类付费资源的 Work 运行切换到共享预占，并同步全部已报告模型用量，不改变未使用新资源的旧 Work 行为。模型地址/修订变化后暂停语义调用，须用户确认配置并重建；未知请求不自动重放。索引与召回的原文不会写入公共用量日志。

用量字段依据：[OpenAI 官方 Embeddings 接口](https://developers.openai.com/api/reference/resources/embeddings/methods/create) 和本机已安装 SDK 的 `CreateEmbeddingResponse.usage`；接口报告 `prompt_tokens` 与 `total_tokens`，文本向量没有生成文本的输出 Token。兼容服务未报告有效输入用量时保持未知，不能据此填 0。

## 实施顺序与验证

1. 候选/提取/来源、范围与到期迁移 → 旧记忆可用、来源/根运行归属、跨账号拒绝、删除传播、重复请求不重复消耗。
2. 候选生成与审阅 → 本机模型替身完成生成、JSON 无效/超时/未知不重放、确认/拒绝、同名冲突及并发确认；所有消耗计入根运行。
3. 范围与语义召回 → 项目/Agent 撤销、到期、不串号、缓存修订/维度、无向量降级说明，使用确定性向量替身验证。
4. 文档运营与 OCR → 同文档重复上传/增量替换、失败状态不冒充就绪、压缩包/页数/大小边界、扫描件与复杂表格限制；真实 OCR 效果仍待所选模型接入。
5. 评测与反馈 → 私有数据集、证据标注、同参数对照、结果与成本持久保存；不以合成数据替代真实 50 题 Recall@10 ≥90%、引用正确率 ≥95% 验收。
6. 中文页面、桌面和窄屏、完整回归、构建 → 备份、迁移与重启，更新验收文档和待真实接入清单，不提交或推送。

## 知识运营的下一批设计（编码前保存）

参考本机 Nexent `parser_runtime.py` 的解析/分块参数入口和 `aidp_mgmt_app.py` 的分块重叠校验，以及[官方开发概览](https://github.com/ModelEngine-Group/nexent/blob/develop/doc/docs/en/developer-guide/overview.md)的分层处理逻辑。此平台保持已有字符分块单位，不把字符数冒充 Token。默认 800 字符、重叠 120，允许 200–4000 字符且重叠不超过块长一半；修改策略仅影响后续导入/显式更新。

文档摘要用于同库/同策略的重复导入去重，旧文档摘要缺失保持未知。更新文档需修订号；新内容解析完成后一次切换当前修订，解析失败保留旧内容。历史分块及其修订元数据保留以便来源追溯，默认检索和重建只用当前修订。解析与向量状态分别显示，不能将关键词就绪说成向量已就绪；迟到的旧索引结果不得覆盖新修订。

OCR 为单独的用户操作：选择本人目标库、已配置的图片理解模型、页面范围与预算后才发送页面图片。扫描 PDF 渲染使用独立子进程、限制文件/页数/页面尺寸/时限，成功文本作为待审阅草稿，确认后导入；超时和未知调用不自动重试。采用 [pypdfium2 官方渲染接口](https://pypdfium2.readthedocs.io/en/stable/python_api.html)，新增该依赖是为了补足现有 pypdf 不提供页面渲染的能力，已有 Pillow 负责像素与编码限制，不安装常驻大型 OCR 模型。遵循 PDF 技能进行实际渲染检查；不对未接入的真实识别效果作承诺。

评测集固定私有库与版本，持久保存问题类别、预期证据/无答案、参数快照、逐题结果、耗时与账本。首批检索实验明确不等于生成答案的引用正确率；人工反馈必须关联本人会话的实际回答，保留证据是否正确、拒答及说明，跨账号均拒绝。合成回归与用户真实题集分开显示。

### 评测与反馈的执行边界

私有评测集使用修订号保存1–50道题，逐题区分事实、无答案、过期、冲突、扫描件与表格；可标注文档修订和具体分块。新实验固定题集、检索设置、当前文档修订和模型修订，任一来源变化则停止并保留部分结果，不能把不同来源的结果当同条件对照。

实验为持久排队任务，由 API 内专用后台协程消费，租约和每题结果持久化；重启后排队任务保留，已开始且结果未知的执行停止等待审阅，不自动重放。每个实验最多100次资源模型调用、512000 Token预算，复用资源账本并逐次重新授权；纯关键词不产生模型费用。单次题目调用仍受 HTTP 超时约束，支持取消。实验不会发送群消息或执行写工具。

结果按题型报告 Recall@10、证据精度、无答案检索准确率与耗时；缺少该类问题时为未知，真实生成答案的引用正确率/拒答正确率不由检索推断。用户可并排选择两次实验，显示来源/设置是否相同以及各自样本数，避免用不完整实验宣称质量已验收。

回答反馈只关联本人会话中已保存的助手消息，支持有帮助/无帮助、人工判断的引用与拒答是否正确、说明及乐观修订更新；删除会话时随消息清理。反馈不自动改写系统提示、权限或长期记忆。
