# Dify 参考工作流前端独立代码审查

2026-11-03。审查者未参与生产实现；依据 WF-D01～08 与本轮前端精确基线审查，不把既有全系统问题混入本轮。此记录是静态调用链确认的代码问题，不冒称真实浏览器已复现。最新结论见文末正式冻结。第一轮结论保留为历史：**不通过，以下三项修复并复审后才能交 QA**。

## WFD-FE01 / P2：同一 MCP 节点的参数文本与撤销后的实际定义不一致

位置：`apps/web/src/features/ask/workflow-editor.tsx` 284～290 的 `argumentsText` 初始化仅依赖 selected；参数文本由 903 行本地 state 驱动，恢复入口 `useWorkflowHistory.restore` 只恢复 definition/layout。

触发：选择 MCP 节点，将工具参数从 A 改成有效 JSON B，点击工具栏撤销。definition 已恢复 A，但选中的 id 未变，effect 不运行，文本框继续显示 B。保存或运行使用 A，界面却展示 B。若在 B 后继续输入无效 JSON，本地 argumentError 与 graphInvalid 也可能在外部恢复后残留，导致已恢复合法定义仍不能保存。

建议：区分外部历史恢复与正在编辑的 JSON 草稿，恢复时同步该节点参数文本和校验状态；不能简单在每个字符渲染后强制格式化 JSON、打断合法的中间输入。验证同一节点 A→B→撤销→重做和无效草稿→恢复，断言 UI 文本及实际提交参数一致。

## WFD-FE02 / P2：旧流程没有显式布局时，撤销移动/整理只恢复模型而不恢复画布坐标

位置：`apps/web/src/features/ask/workflow-editor.tsx` 229～233，位置优先 `layout[id]`，缺失则复用 `previous.position`。

触发：打开合法旧流程 `layout={}`，移动一个节点或点击整理。撤销恢复原 `layout={}` 后，节点投影因缺少显式坐标而沿用刚移动/整理后的 previous.position；页面仍显示新位置，同时 definition/layout 已等于已保存状态，dirty=false。刷新后才回到原默认位置。这违反 WF-D07 的可撤销编辑，尤其影响本轮兼容的旧数据。

建议：历史恢复时有明确的恢复标记/规范化坐标，让被撤销的缺省布局重新投影为其缺省位置，同时保留普通运行状态更新期间正在拖动节点的位置。验证旧空布局移动与整理后撤销/重做的真实 DOM 坐标，不只检查布局对象。

## WFD-FE03 / P2：合法已处理错误的真实输出被隐藏，也不能复用给下游模板

位置：`apps/web/src/features/ask/workflow-variables.tsx` 30 只允许 SUCCEEDED 的输出；`workflows.tsx` 256～257 为引用变量只查 node.completed，忽略 node.handled。

触发：转换节点失败后通过已有错误分支被处理，其 `node.handled` 含真实输出（如 TRANSFORM_FAILED 错误对象），该输出写入执行 values 且供下游引用。变量检查却显示“没有可用输出”；选择后续模板节点复用运行输入时，该上游引用测试值为空，需手工补充，不能复现同一真实运行。

建议：对 HANDLED 明确展示“已处理错误”的真实输出并允许复制/引用；复用应取该节点最近一次执行的有效 completed/handled 结果，不能跳过最近失败/开始而拿旧成功值。未运行、FAILED、WAITING_APPROVAL 等仍不能伪造成功输出。验证处理分支→下游模板实际运行后检查/复用，以及失败状态不残留旧值。

## 已检查且未发现阻塞的问题

模板常量不包含用户资源/凭据，五种场景定义独立生成；主变量选择采用必经前驱交集，旧开始 id 继续保留；检查请求绑定流程 id、请求序号和定义 key，修改后不会沿用旧检查通过；undo/redo 按钮及快捷键受 locked 约束，输入控件保留原生撤销；变量检查按运行 id 重建，复用受 dirty/修订/版本限制；没有新工作流 SSE/202 通道。上述结论是静态审查范围，不替代构建、实际页面及权限集成测试。
