用户授权直接实施和验证。复用现有React Flow、15类节点、LangGraph执行、发布版本和持久任务审批，保留既有工作流及运行记录，不提交推送。

参考[Dify Workflow Studio](https://dify.ai/workflows)、[Dify实时调试说明](https://dify.ai/blog/dify-1-5-0-real-time-workflow-debugging-that-actually-works)及[官方运行日志说明](https://github.com/langgenius/dify-docs/blob/main/en/cloud/use-dify/monitor/logs.mdx)：先创建应用进入画布，配置与测试并列，节点状态与输入输出可追溯。独立实现本平台界面，不迁移Dify运行时或品牌。

## 交互与实现

1. 列表页提供创建、打开、删除与发布状态。创建只需名称、默认模型和模板；随后进入占满内容区的独立画布，顶部保存、测试、运行历史及发布按钮。模型指令、Schema和预算移到流程设置面板。
2. 画布内提供节点面板、点击添加、顺序节点快捷插入、拖动连线、复制和删除。简单直线插入/删除自动衔接；分支仍由明确出口连线控制。最后一个开始/结束节点受保护，删除时同步清理布局和相关引用。
3. 点击节点在右侧配置，沿用原有节点参数与资源选择。草稿可保存未配置完成的节点和未接通的图；只读预览和发布仍必须通过完整结构、资源、归属与版本校验，未完成草稿不被当作已测试。
4. 测试面板支持整个流程与单节点输入、真实结果、运行历史和节点轨迹。单节点调试使用受限临时图及独立运行记录，只执行所选只读节点；代码/人工审批必须通过持久任务入口，不绕过审批，单节点成功不解锁整个流程发布。
5. 沿用已有节点事件，运行时轮询真实记录，在节点与轨迹显示未运行、运行中、成功、失败、已处理错误与等待审批，并展示实际输入、输出和耗时。历史运行查看其执行快照，不把旧结果贴到已修改的图上；未知结果不自动重发。
6. 保存使用修订号防止覆盖；测试前保存当前草稿并固定修订，运行期间禁止编辑当前测试图。整体测试成功才可发布，已发布版本保持不可变。保留Schema表单、子流程/循环/并行、路由、任务审批和API发布入口。

## 执行状态

本轮已实现并部署，数据库仍为070，无新增依赖或迁移。工作流列表与画布工作台分开；创建后直接进入画布，通过节点库添加、复制、删除、拖动连线，右侧配置节点，顶部保存、测试和发布。桌面及390px布局已有实际Chrome操作验证。

草稿接口新增可选`allow_incomplete`，旧调用默认仍做完整校验；未完成节点可以暂存，执行与发布继续严格校验。单节点测试只运行受限临时图，保留独立历史，但不解锁整体发布。只读执行支持客户端运行编号，冲突返回409；页面按该编号读取真实事件，网络结果未知时不自动重发。代码与人工确认节点仍通过任务与审批执行。

画布展示运行中、成功、失败、已处理错误和等待审批等状态；轨迹显示实际输入、输出和耗时。历史使用对应运行的定义快照，发布版本只读；编辑当前草稿不会把历史结果套到新节点定义上。

### 使用方式与边界

工作流 → 新建工作流 → 填名称、选择空白或AI问答模板 → 进入画布 → 添加并配置节点。选中节点可单独测试；顶部“测试运行”执行整个流程，通过后“发布版本”。“运行历史”查看当次画布和节点详情；持久流程通过“查看任务与审批”继续批准操作。

真实服务商、真实业务数据及联网效果仍按用户要求暂缓联调，见[integration-checklist.md](integration-checklist.md)。本轮没有引入Dify运行时，也不宣称与Dify全部节点生态相同。
