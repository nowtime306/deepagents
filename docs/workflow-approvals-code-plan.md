## 用户行为

- 流程增加显式执行方式：只读（默认，旧流程兼容）或任务执行。新增“人工审批”和“Python代码”节点只允许任务执行；Ask、团队只读工具、短流程/API Key入口拒绝任务流程，不把持久任务伪装成同步只读调用。
- 画布配置审批说明；代码固定在草稿/发布版本，最多8000字符，标准输入接收节点文本，标准输出/错误输出合并为受控节点结果，最长60秒。执行前展示代码、输入预览及完整输入/代码摘要，用户批准后才能执行；只允许批准或拒绝，不能在审批中悄悄改变已审核的代码。
- 从流程调试区创建持久任务，显示任务链接、审批、节点证据与成果。草稿必须在实际任务中成功完成且资源一致才允许发布；发布版本仍不可修改。
- 暂停/审批后重建执行图并使用同一任务检查点恢复。已经完成的模型、工具和代码节点不重放。拒绝、过期、撤权、取消、预算耗尽、环境故障分别保留原因；结果未知进入核查，不自动重新执行代码或外部调用。

## 实现与边界

1. Definition新增默认只读的执行方式，校验15类节点。工作流版本资源固定及当前权限在每个节点和模型/工具调用前检查；代码/审批只在顶层持久图开放，组合节点暂只允许已发布只读子流程，避免子流程中断恢复时重复执行前面的迭代或并行副作用。此限制必须同时在服务端和中文页面说明。
2. 独立映射表连接Work根运行和workflow_runs，保存不可变定义、输入、资源、来源修订/版本。任务属于发起人；读流程需要workflows.read，执行同时需要workflows.execute及Work权限。API启动清理不得把独立Work后台仍持有或已正常暂停的流程判成失败；过期/取消/失效归属必须同步为核查或终止。
3. 编译器可选持久检查点，默认旧短流程行为不变。审批节点在任何副作用前interrupt。批准后消费与代码/输入摘要完全匹配的单次操作凭据；人工确认也有独立操作名称，不冒用模型的execute。复用已有操作表的任意文本名称，不添加无用枚举迁移。
4. 代码通过受控文件接口写入任务专属工作区，固定ASCII节点路径；批准后重新写入/核对固定字节，不能执行被旧任务文件或链接替换的脚本。通过原有非特权命令通道执行，工作区、输入输出、时间/文件限制及出站域名授权继续生效。不使用宿主eval/exec，不在上下文或成果中写入服务端凭证。
5. 根预算跨审批恢复从持久节点证据和统一用量账本读取，重复进入中断节点不重复预占，不能因恢复重置预算。模型与检索继续计入Work根账本，避免同时挂两份回调造成重复记录。节点错误不将未知模型请求包装为安全错误出口。
6. 中文调试区跳转任务；任务页区分人工确认、代码审批和普通命令，显示批准/拒绝、输入/代码摘要、节点进度及有证据的最终结果。沿用ChatGPT式收起细节，默认不展示内部租约与实现参数。
