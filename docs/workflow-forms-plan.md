# 结构化工作流输入表单实施计划

2026-11-01，onwer_agent。基线为浏览器工作台交付、后端299 / Chrome29 / 60迁移。继续阶段六剩余项，不覆盖已有数据或发布版本，不提交推送。

## 设计

- 根据正在运行的草稿或不可变发布版本的输入Schema生成中文表单。文本、数字、布尔、枚举、对象和数组使用对应控件，必填、范围、长度和数组项数给出明确提示；复杂结构仍可切换原始文本/JSON输入。根字符串沿用现有文本框，保持旧页面和接口兼容。
- 选择发布版本时读取该版本的输入Schema，不从当前草稿猜测；切换模式不清空现有内容。无法解析的既有JSON不静默覆盖，用户明确选择“按结构新建”才初始化。
- 可选字段未启用时不发送；启用后的字段递归编辑。大数组不一次生成无限控件，超出表单展示上限时使用JSON输入并继续由服务端校验。表单最终仍传现有有界text字段，不增加执行接口或另一套解释器。
- 浏览器校验用于及时反馈；服务端现有Schema校验继续在创建运行/模型调用之前执行。拒绝未知字段、错误类型和无穷值的责任不移到前端。发布记录不回写，跨账号版本Schema仍受本人资源权限约束。

## 实施与验收

1. 发布列表补输入Schema → 隔离数据库证明编辑草稿不改变已发布Schema，其他账号不可读取。
2. 自动表单及现有测试入口接入 → Chrome实际完成对象/必填/数字/布尔/枚举/数组输入，校验失败不请求执行；草稿与版本切换使用对应约束，文本/JSON模式保留内容。
3. 生产构建、类型/静态检查、定向后端与页面验证 → 只读元数据不迁移数据库，服务重启后复验；按明确记录ID清理本机纯转换工作流，不发真实模型请求。

本批不宣称完成条件循环、工作流持久审批/代码节点或会话授权引用，它们继续按原阶段六计划分别实施。表单Schema只使用已支持的子集，不引入远程Schema解析或执行表达式；不增加新的依赖。

## 实现与验收

自动表单、原始JSON切换、可选字段、递归对象/数组、枚举/布尔/数值与必填范围校验已实现。超过30项的数组改用JSON模式，不删除原值；解析失败的既有内容不在后台覆盖。Unicode长度按字符而非UTF-16单位判断，对象枚举忽略键顺序，原型名称的未声明字段同样拒绝。服务端保持最终校验。

发布列表返回该版本固定的输入Schema，选择版本时不借用当前草稿。后端定向 **8 passed（10.96秒）**，含新增不可变Schema/越权/无效输入不创建运行的回归；页面定向 **3 passed（5.6秒）**，包含新表单、旧组合画布和会话分支。实际纯转换流程验证整型范围、单个emoji不满足两字符、布尔、枚举、数组增删/上限、可选字段取消、非法JSON保持、未知字段拒绝、JSON往返和发布版本切换；不调用真实模型。
