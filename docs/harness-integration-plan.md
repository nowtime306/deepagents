# Harness 与 Token 用量实施方案

更新：2026-10-31。依据用户关联对话「开源项目排行」（6ae5aea1-5f6c-83ee-8d85-831c7cb942db）的完整设计，以及当前项目实现。

## 实施边界
- 保留 Deep Agents 原生模型与工具循环、LangGraph 检查点、流式事件；不嵌入 OpenClaw Gateway，不额外套一层模型循环。
- 借鉴 OpenClaw 的运行控制、上下文装配、工具授权、生命周期与恢复思路，统一平台 Harness 工厂。平台模式策略与 SDK 的供应商 HarnessProfile 分开。
- Ask 与 Work 分别构建图，继续使用既有独立线程、任务归属、审批与 Worker 租约。Ask 只读技能与已授权检索/MCP/联网工具，禁用文件写入、命令和委派；Work 保留计划、子智能体、审批和受控工作区。
- Workflow 的 Agent 节点复用同一工厂；确定性工作流调度不改为模型循环。已有工作流工具继续沿用父任务预算。
- 使用既有取消、超时、版本校验和资源撤权机制。Ask 增加每轮模型调用与 Token 预算；Work 继续使用持久预算和租约。

## 用量统计
- 以 run 为一轮，聚合本轮所有模型调用；保留输入、输出、调用次数与未知/进行中数量。历史轮次通过归属校验读取，刷新页面可恢复。
- 实际数字仅来自供应商 usage；未返回或中断的调用标注未知，不当成零。模型循环、摘要和子智能体产生的调用计入对应运行，父子回调去重。
- 发送前展示本地粗估输入和单次输出预留上限；计入历史、当前问题、附件、指令和工具开销。图片按固定粗估预留，不计算 Base64 长度。不是供应商账单或整轮精确预测。
- 调用时记录实际装配消息的输入估算和输出预留，便于供应商统计缺失时说明不完整状态。估算不发送请求，不暴露私有提示词或密钥。

## 验收
1. 图工厂统一 → 使用协议替身验证 Ask 的只读工具边界、工具循环及 Work 原审批。
2. 用量持久化与 API → 隔离数据库测试多次调用合计、未知状态、跨用户隔离、图片估算和历史恢复。
3. 中文页面 → 实际浏览器验证发送前估算、每轮输入输出与会话合计，生产构建通过。
4. 迁移与运行 → 备份、应用增量迁移、重启本项目服务并检查健康，不提交或推送，不改用户密钥；跳过真实外部模型联调。

## 本轮落地与使用

- app/harness.py 提供统一工厂、模式策略和运行钩子；graphs.py 的 Ask/Work 以及工作流 Agent 节点都使用该入口。当前继续复用 Runtime、CapabilityService、WorkWorker 与原审批系统，不新增重复的调度服务。
- Ask 使用只读文件工具白名单，替换 SDK 子智能体中间件以移除 task 工具，禁用执行和写入。既有 Skills 的受权只读后端保持有效；Ask 继续使用旧消息 reducer 兼容已保存会话。
- Ask 模型调用前及应用工具执行前检查取消状态；模型修订校验和逐轮预算沿用数据库账本。Work 保留持久预算、租约、暂停/恢复与 verifier。
- 聊天未填最大输出时明确使用 4,096；配置值仍可覆盖，Work 单次限制最多 8,192。Ask 单轮最多 12 次模型调用、64,000 Token；统计缺失时以粗估和输出预留计算后续预算，不能称为供应商账单硬上限。
- 迁移 042_harness_usage.sql 为账本新增独立估算字段与查询索引；不重算旧记录，不修改模型凭证。

### 页面使用
1. 选择模型和智能体，输入问题后，输入区展示首个模型请求的预计输入及单次输出上限；展开可查看估算范围。
2. 发送后，每轮末尾展示实际输入、输出和调用数。输入区附近展示会话累计，刷新或重新打开历史仍可读取。
3. 多次工具循环、摘要和子智能体会追加模型用量。服务商未报告或中断的调用标注未知，不当成零。
4. 任务工作台同样提供提交前估算和输入/输出累计；子工作流计入父任务视图，账本本身不重复新增同一调用。

### 接口
- POST /api/v1/usage/estimate：当前草稿本地粗估，不请求外部模型。
- GET /api/v1/conversations/{id}/usage：本账号会话按运行聚合及累计。
- GET /api/v1/work-runs/{id}/usage：本账号任务及其子工作流累计。

发送前估算并未运行检索或读取未来工具结果；历史粗估最多 100 条，与 SDK 实际压缩后的上下文可能不同。调用时账本另外记录装配后消息的估算。实际用量与估算存储、展示分开，未来可接供应商 tokenizer 校准。
