# 模型能力接入计划

> 2026-11-01 最新状态见 [本机交付记录](final-delivery-2026-11-01.md) 和 [实现与验收记录](implementation-verification.md)；下文是按日期保留的开发历史，早期“尚未实现”不作为当前状态。十种用途不等于任意服务商/协议组合均支持，真实效果仍按接入清单逐项验证。

2026-10-30，用户要求将已有模型设置中的全部类型接入平台，并参考本地 Nexent 项目。现有模型配置、密钥和账号数据必须保留；真实外部模型联调按用户此前要求暂缓，使用官方协议文档、隔离测试和可控协议替身验证。

1. 重排：为知识库绑定可启用的重排模型，先检索候选片段再调用对应服务商的重排接口，保留来源，失败时清晰提示并回退。提供有代表性的数据进行连接测试与排序验证。
2. 图片理解、视频理解、音频理解：支持上传有大小和类型限制的输入文件，提供对应模型选择、传输适配与结果展示；明确不支持的供应商协议，不将本机路径暴露给外部服务。
3. 图片生成、语音合成：接入支持的服务商生成接口，结果以可访问的文件形式保存、展示与播放；处理远程临时地址、失败和鉴权，不将凭证传给前端。
4. 语音识别：支持音频上传与转写，校验输入类型、大小和协议，并提供中文结果与错误提示。
5. 多模态向量：按服务商实际协议实现图片/文本向量化、持久化与检索，确保模型和向量维度一致；普通文本向量库保持兼容。
6. 对所有可执行类型实现适当的连接或样本测试，不能把仅保存配置误标为连接成功；更新中文页面、使用说明和进度记录。测试应覆盖认证与归属、协议请求、成功/失败、来源追踪、数据库迁移及浏览器操作。

服务商的多模态协议、输入形式和可用模型不完全相同，不能把一个 OpenAI 兼容标签当作所有类型的统一协议。以 Nexent 已有实现及各提供商官方文档为依据，明确每种已支持的组合和尚未支持的组合。优先实现用户当前使用的硅基流动重排。

## 当前进度

已接入兼容 `/rerank` 的文本重排：模型管理可测试连接；在知识库详情选择或取消重排模型，关键词或混合检索先召回最多 20 个候选，再按服务端返回的相关度排序并保留来源。重排失败时显示提示并保留原有顺序。已有知识库可绑定，无需重建。迁移 `005_knowledge_rerank.sql` 已应用本地数据库。

后端 36 项测试通过（包括模拟协议往返、重排排序和失败回退），浏览器 5 项回归测试通过；真实硅基流动服务尚未联调。图片、视频、音频理解、生成、语音识别/合成和多模态向量仍待实现；当前不能将它们描述为已接入。

## 语音合成实施细化

首版面向支持 `/audio/speech` 且接受 `model`、`input`、`voice`、`response_format=mp3` 的服务，包含硅基流动和 OpenAI 兼容实现；音色由用户填写服务商支持的值，不假定不同服务商音色通用。登录用户选择启用的语音合成模型并输入文本生成，服务端使用加密保存的密钥调用服务，限制文本和响应大小，音频持久化在平台目录并以账号归属控制播放、下载和删除。密钥和外部响应错误不返回浏览器。其他协议明确不支持；调用会将文本发送给所选服务商，可能产生费用。测试以受控传输模拟服务商，真实外部联调暂缓。协议依据：[硅基流动语音合成接口](https://docs.siliconflow.cn/docs/api/audio-speech-post)。

## 语音识别实施细化

语音识别首版支持 `/audio/transcriptions` 的 multipart 协议：用户选择启用的语音识别模型并上传最多 10 MiB 的 MP3、WAV、M4A、MP4、WEBM、OGG 或 FLAC 音频，服务端校验后转发文件和模型名，展示返回文本；本阶段不保存上传文件或识别历史。不同服务商支持的实际格式与模型以其文档为准。请求仅登录用户可发起，外部错误不回传密钥或原始服务错误；真实外部联调暂缓。协议依据：[硅基流动语音识别接口](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post)和 [OpenAI 语音转写接口](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create)。

## 2026-10-30 语音阶段进度

已开放“语音合成”页面：启用且使用兼容协议的语音合成模型可按用户指定音色生成 MP3；音频保存在平台数据目录，记录按账号隔离，支持播放、下载和删除。使用 `010_speech_outputs.sql` 保存归属及元数据，已应用本地数据库。语音识别支持选择兼容模型并上传最多 10 MiB 的音频，识别文本仅本次显示，不保存原始音频或识别记录。模型连接检测仍需在页面使用实际音色或音频测试，不会把语音类型当聊天检测。两项功能仅适用于服务商实际实现相应接口的模型，不代表所有标记为 OpenAI 兼容的供应商均支持。

后端完整回归 51 项通过；页面回归 6 项通过，其中语音服务请求和结果使用拦截替身；Webpack 生产构建通过。Turbopack 构建因启动子进程失败，未通过。没有使用真实外部模型或音色联调。图片、视频、音频理解、图片生成和多模态向量仍待接入。

## 图片理解实施细化

首版对支持 `/chat/completions` 图文内容的图片理解模型，提供登录用户上传单张 PNG、JPEG 或 WebP（最多 5 MiB）并输入问题；服务端验证文件签名，使用 data URL 将图片与问题发给模型，显示文字结果，不保存图片和结果。限制响应大小和超时，不向浏览器暴露模型密钥或原始供应商错误。仅适配明确支持此图文协议的模型，其他协议不视为已接入。真实服务联调暂缓。依据：[OpenAI 图文输入说明](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat)。

## 图片生成实施细化

首版支持 `/images/generations` 返回 `data[0].b64_json` 且默认输出 PNG 的模型，提交模型名和提示词生成一张图片。图片及元数据保存在平台目录和数据库，按账号隔离展示、下载和删除，限制响应与文件大小，不跟随供应商返回的 URL。只返回 URL 的图片服务（包括部分供应商的原生接口）需单独适配，不能称为已支持；不同模型参数能力不同，首版不发送可选尺寸等参数。真实外部联调暂缓。依据：[OpenAI 图片生成接口](https://developers.openai.com/api/reference/resources/images/methods/generate)。

## 2026-10-30 图片阶段进度

图片理解首版已开放：选择启用的兼容图文模型，上传单张 PNG、JPEG 或 WebP 并输入问题，结果仅当次显示。图片生成首版支持 `/images/generations` 直接返回 Base64 PNG，生成的图片按账号保存，可展示、下载和删除；仅返回 URL 的服务尚未适配。迁移 `011_generated_images.sql` 已应用本地数据库。真实服务是否支持这些请求及具体模型仍需联调，不能把所有 OpenAI 兼容服务视为支持图片生成。

后端 55 项测试、浏览器 7 项测试、Webpack 生产构建通过；图片与语音的页面生成和识别使用协议或浏览器替身验证，没有进行真实外部模型联调。视频理解、音频理解和多模态向量仍待实现；模型原生联网、完整任务工作台和可视化工作流也尚未完成。上文先前“图片理解及生成待实现”的阶段描述已由本节进度更新。

## 音频理解实施细化

对支持 Chat Completions `input_audio` 内容结构的音频理解模型，提供最多 10 MiB 的 WAV 或 MP3 文件与问题；服务端检查音频签名并发送 Base64 内容，展示文字回答，不保存音频或回答。仅支持供应商实际实现该协议的模型；语音识别和音频理解是不同用途。真实外部联调暂缓。依据：[OpenAI 音频聊天接口](https://developers.openai.com/api/docs/guides/audio-chat-completions)。


## 视频理解实施细化

首版适配阿里云百炼 OpenAI 兼容接口的 `video_url` 消息格式；只有服务商选为 DashScope 且模型用途为视频理解的启用模型可选。上传不超过 10 MiB 的 MP4 视频和问题，构造 Base64 Data URL，不保存视频和回答。Qwen-VL 仅处理视觉内容，支持音频与否取决于具体模型；其他服务商和接口暂不支持。真实外部联调暂缓。依据：[百炼 OpenAI 兼容聊天接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。

## 音频与视频理解进度

音频理解支持兼容 Chat Completions `input_audio` 的模型，上传 WAV 或 MP3 并提问；百炼视频理解支持兼容接口的 `video_url`，上传 MP4 并提问。它们均不保存用户文件或结果；其他供应商能否支持相同消息格式须以其实际接口为准，视频当前仅开放百炼服务商。相关协议、输入校验和页面交互已使用替身验证，外部真实模型未联调。此前“音频和视频理解待实现”的阶段说明以本节为准。多模态向量仍待实现。

## 多模态向量实施细化

首版新增百炼多模态 Embedding 原生协议：管理员在模型管理选择该协议及服务地址（例如 `https://dashscope.aliyuncs.com/api/v1`），按服务商文档调用 `/services/embeddings/multimodal-embedding/multimodal-embedding`。知识库可绑定一个独立的多模态模型，上传图片生成向量，以文本搜索图片；图片和索引分别持久化，结果只向所属账号展示。首次绑定固定模型名称、地址和向量维度；配置发生变化或维度不符时拒绝混用，需重建索引，原有文本知识库不受影响。支持 PNG、JPEG、WebP 和输入大小限制，不跟随远程资源地址。实际模型需支持文本和图片处于同一向量空间。验证协议替身、索引持久化、越权和维度不一致；外部联调暂缓。[百炼接口文档](https://help.aliyun.com/zh/model-studio/multimodal-embedding-api-reference)。

## 多模态图片检索进度

百炼原生多模态向量协议已接入：知识库可固定模型并上传图片，以文本查询相似图片；图片、元数据及 Qdrant 索引持久化。模型名称、地址或输出维度发生变化时拒绝继续混用旧索引。当前支持 PNG、JPEG、WebP 和文本搜图，不支持图搜图、视频向量或在 Agent 对话中返回图片引用；更换模型需新建知识库。迁移 `012_multimodal_knowledge.sql` 已应用本地数据库。

后端 61 项测试通过，覆盖协议替身、账号隔离、模型和维度变化、图片搜索及知识库删除；浏览器 7 项回归通过，其中多模态上传与检索请求使用拦截替身；Webpack 生产构建通过。真实百炼或其他外部模型联调仍未进行。上文旧的“多模态向量待实现”描述以本节为准。

## 硅基流动图片生成适配细化

硅基流动图片生成返回 `images[0].url` 且链接会过期；按其原生请求结构发送模型和提示词，及时下载并保存结果，不转发 API 密钥。下载仅允许 HTTPS、无重定向、指定文档示例所使用的官方对象存储主机 `sf-maas-uat-prod.oss-cn-shanghai.aliyuncs.com`，限制响应大小并校验 PNG；其他主机或格式明确失败，不以宽泛网络访问替代校验。此限制意味着供应商若使用不同存储域名或格式，需后续按其官方资料扩展。使用协议替身验证，真实服务暂不联调。[硅基流动图片接口](https://docs.siliconflow.cn/docs/api/images-generations-post)。

硅基流动图片生成适配已实现：选择 SiliconFlow 服务商时处理 `images[0].url` 并转存 PNG，仅接受文档示例中的指定对象存储主机；下载不发送模型密钥且不跟随跳转。协议与非法地址拒绝已通过替身测试，真实硅基流动接口及其他可能的存储主机仍未联调。上文“仅返回 URL 的服务尚未适配”以本节为准。
